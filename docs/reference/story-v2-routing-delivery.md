# Story v2 与内容路由交付说明

## 范围与验收边界

主体交付包括独立 `lore_select`、跨仓生成端与代表样例；本轮按用户裁定修复 A01–A14，归档失败采用绑定原判断回合的自动重试，补摘要语义字段，第一版激活协议正式收敛。不提交、推送或发布；真实 LLM、浏览器实机、全量语料逐条语义复核及两种召回原文粒度的真实效果/费用比较继续暂缓。实现与自动化验证不等于这些效果验收完成；修复后实测见[验收记录](../planning/2026-10-04-story-v2-content-routing-acceptance-progress.md)第 10 节。

## 消费契约

- 读取权限只由**条目自身** `extra.lore.audiences` 决定（逐条目声明；书级 `lore.audiences` 与旧包兼容映射均已移除）；显式 `[]` 是不授权。依赖、EJS `lore.get/list`、旧模板及 Delta 均不能扩大权限。无声明条目/第三方资料不注入，并给出可定位诊断。
- Agent 的 `worldBookEnabled/worldBookIds` 控件、运行字段和新生成默认配置已退役，从包历史默认值推导权限的兼容映射也已移除。用户自建书迁移旧授权时改写为条目级读取范围，落库失败保留暂存并可重试，不得覆盖显式空范围。
- 旧 Story 继续原记忆、预设及 Delta 路径；新增区占位在旧模式为空。新模式不建立 Delta 会话，不把消息列表压成单条 system，不把普通档转换成测试档。
- 第 1 区常驻资料；第 2 区全部有效阶段归档年表；第 3 区按当前地理路径的层级包含匹配区域资料；第 4 区全部未归档的窗口外摘要与最近 N>0 完整回合原文；第 5 区必选/选中的本轮资料、剧情指引、召回及状态。显式 `section` 优先；未声明分区时静态默认第 1 区，动态默认第 5 区必选。分区不等于冻结，开局固定结果须显式声明 `evaluation: "onCreate"`。
- Story v2 在读取当前地点时，经现行地图索引按最深具名地点补全省份/地块和国家；保留原角色位置，不借国家锚点或旧落位猜省份。读取门、区域选择和 EJS 间接读取共用补全结果。没有地图或认不出地点时保留原路径；热换地图后读取新索引。
- 第 3 区的诊断快照键包含实际区域条目的正文和路由元数据，同一区域内地点文字变化不单独使其失效。远方话题不替换当地背景；远方选中地点的父级依赖进入第 5 区，不混入当地第 3 区。没有另建持久化区域缓存。
- 位置、在场人物、关键词仍按正向 OR 作为相关性条件；排除词优先。新增 `activation.readWhen.any` 作为**仅 Story v2** 的确定性读取门：分支内 AND、分支间 OR，支持位置、提及关键词与年度日期窗口。未命中不能经补充池、回退、依赖或同次 EJS 读取绕过；命中且 `required: true` 则必选。旧模式不应用此新增门，权限/停用/排除/依赖检查仍双模式共用。位置段包含命中，不改变地图落位，也不把人物资料激活当作安排人物出场。完整协议与限制见[求值与读取门](lore-evaluation-and-read-gates.md)。

位置放宽已按上述裁定实施：`lore-selection.ts` 的区域命中与候选判定共用包含匹配函数，空声明不命中，不跨路径层级拼接匹配。位置放宽的专项回归覆盖包含方向、层级边界、空值、快照稳定性及权限/停用/硬排除/依赖限制；下文既有全量闸门记录不作为本次改动后的全量验证结果。

## 正式回合、记忆来源与失败恢复

新写入消息通过 `storyTurnStatus` 和 `storyTurnKey` 区分 pending、accepted、failed 及所属输入；诊断/侧链消息不是 Story 正文。失败尝试不进入窗口或摘要补建，重试按原回合排除旧尝试，未打标的历史消息保留兼容判据。N 只接受正整数，设置与运行时一致；摘要完整保留全部有效片段，不再静默截成 8 段。

v2 `{{AGENT.MEMORY_SUMMARY}}` 向后置剧情检查提供 segments 文本投影，原结构 JSON 保留供代码解析；旧模式仍消费原摘要文本，不全局覆盖共享占位语义。

摘要保存人物、地点、主题与原回合游戏时间范围。时间来自消息持久化的回合事实，不使用补建时当前档案时间；历史缺失保持未知。来源契约共用完整有序消息 ID 集合与角色/正文指纹，指纹不包含物理 ID，单档备份重映射时保留。旧 v2 记录缺指纹不能证明正文未改，读取失效并可补建，不自动把现有正文追认为旧摘要来源。

召回展开保留摘要及档案来源回合的人物、地点、主题和游戏时间范围；原文因预算省略或已在近期窗口内时，这些定位信息仍保留。LLM 的合法空数组不重试；空响应与格式错误最多进行一次格式重试，网络错误沿用客户端既有重试设置。失败后只按当前查询补取最多3条有文字相关性的有效记忆，没有匹配仍明确回报失败；取消不触发重试或补取。重试及降级经 `notices` 和逐次 provider 记录保留，两次格式请求的 token / 缓存用量累计，编号与提示标签不参与降级相关性评分。

最终记忆提交取得 per-save 锁后，在同一事务中重读存档、正式回合、完整来源与覆盖片段修订；取消、删档、回退、正文修订或覆盖变化均不接受迟到结果。同来源摘要替换会使关联归档失效，诊断保留，不猜测新片段映射；第 2 区不展示失效归档，剩余有效摘要恢复未归档语义。

Dexie v29 `storyArchiveRetries` 保存通过判断的原回合归档草稿、完整来源与覆盖修订；整个提交失败时也保存原摘要草稿。自动重试仍绑定原判断回合与原结局证据，不要求下一轮正文重复结局。成功原子补写/落档并删除草稿；来源失效清理，覆盖替换保留失效原因。重试记录随删档、快照回退、整库和单档备份处理；手动纠正入口不是本轮自动恢复的前提。

## 资料选择与预算

`lore_select` 使用自己的端点、模型、参数、系统提示与模板。模板只替换 `{{LORE_CATALOG}}`，不展开通用世界书占位符或 EJS。目录必须同时满足 Story 和选择器权限；只提供名称、短摘要、字符数与本轮上下文，不提供正文。候选 C 与补充 E 各最多 80 条，补充去重后最多 15 个根条目，其依赖闭包另行展开。缺端点、网络失败或非法输出回退为确定性候选；未知引用被拒绝。取消不执行回退。

依赖按完整闭包展开，循环、缺失、停用、硬排除、不可读或未通过 v2 强激活的依赖会阻止依赖根；依赖不能授权。选择之后、EJS 之前按预算移除可选根及其独占依赖，保留共享/必选依赖；仍不足时整体移除可选召回块。不裁剪第 2 区总览、第 4 区摘要与窗口原文，也不截断必选资料。剩余条目单轮预渲染一次；ST 字面定义独立于正文选择和预算供值，条件定义不从未求值 EJS 中无条件提取。

预算以字符数 / 1.5 粗估输入 token，并使用最终请求体（含覆盖和删除）对应的输出预留。调试面板分别展示固定资料、长期总览、区域资料、摘要、原文、本轮资料、召回、当前事实/指引及输出预留，并定位预算移除和逐条选择/排除原因。EJS 展开后仍超限时停止 Story 请求并保留诊断；不发送已知超限请求，也不回落旧模式。估算及预留不是服务商精确 token 计费。

## 内容作者与生成

生成包保留 `formatVersion: 1`，显式声明 `loreRoutingVersion: 1` 和 `minEngineVersion`。新路由修订在安装时验证字段类型、Agent ID、身份、依赖存在性/权限与循环，并拒绝书级 `audiences`/`section`、要求逐条目声明；旧包兼容映射已移除。修订号不替代最低引擎版本；旧历史引擎没有兼容保证。

私有内容仓新增：

1. `data/routing/lore-routing.json`：按 `bookId#uid` 定位作者声明，不改正文。
2. `tools/lore-routing.mjs`：构建时合并元数据，支持显式 `parts`；子条目使用永久 UID/键，正文拼接必须逐字还原父正文，拒绝自动拆分 EJS。
3. `tools/apply-lore-routing.mjs`：卡导入后刷新 overlay 源文件的非拆分元数据。拆分父正文仍保持原始形态，拆分结果通过构建包消费；不要把生成子条目反写成原始卡。
4. `tools/normalize-story-presets.ts`：复用引擎五区规则刷新作者预设，不改普通指令正文。相邻两仓目录约定见私有 README。
5. `tools/build-pack.mjs`：构建包与 `dist/lore-split-report.json`。父启用 token 依据显式来源映射展开为子 token，普通档与测试档相同；安装和“先装拆分新版内容、后导入旧档”均复用同一映射。只替换可证明的父来源 token，不按书名猜测、不扩大权限，不转换记忆与测试标记。
6. `data/worldbooks/README.md`：作者分册解释 audiences、分区、激活、依赖、来源拆分、重导入刷新及双模式消费边界。

代表样例包括城市区域、人物依赖种族、交易/锻造活动；合成测试覆盖城市/港区的逐字拆分。真实角色原停用状态保留。本轮未宣称完整语料均完成分区拆分与语义复核。历史默认指纹不得被当前新默认重新生成覆盖。

## 临时决定与保留项

沿用 handoff 第 6 节：N 复用正文历史层数，缺省 6；普通预设条目在第 4 区原文之前为前导 system、之后归末尾 user；分区负责的旧占位符在新模式为空。召回复用现有 LLM/Embedding 选择，两种原文粒度保留可切换；不做第 2/5 区全局去重。关闭实验模式退出测试档且永久标记不撤销。

本轮修复后完整 `npm run gates` 通过：427 个测试文件、9837 项通过、8 项跳过；Knip 135 条既有基线无新增。新生成实际内容包跨仓契约 6 项通过，作者路由 3 项通过，两仓修改文本编码/JSON 与私有密钥扫描通过。结果不沿用修复前统计。

剩余产品验收：真实模型输出质量与消耗比较、浏览器交互、全量资料语义复核。具名并发回归不代表穷尽全部 UI 交错；已有侧链/剧情/领域提交不提供跨管线原子回退。R01 只重放已通过判断的有效草稿，不将未得到有效输出的网络/解析失败伪造成归档决策。执行记录见[验收记录第 10 节](../planning/2026-10-04-story-v2-content-routing-acceptance-progress.md#10-本轮授权修复与修复后验证)与 [CHANGELOG](../CHANGELOG.md)。
