## 0. 一句话架构

v1 的地图是「不可变包 + 派生投影」；v1.2 第一次给地块引入**事实态** ——
AI 叙事产生的地块状态、发展度进度、建筑记录与编年史。事实与派生**分仓存放**
（`worldFlags.mapFacts`，按地块名为键，**永不随 packStamp 清空**），
一切按期结算（状态到期 / 每月效果 / 每月收益）由一个新的**回合驱动时间账本
（TimeLedger）**统一驱动 —— 集中调度、分散结算、没有自走时钟。

## 1. 功能契约

### F1 地块状态（tile status）

AI 叙述者可以给**任意地块**（含海/不可通行块）挂限时或永久状态，形如：
`洪水 ｜ 洪水席卷了银帆城 ｜ 每月发展度 −2 ｜ 30 天`。

- 结构：`{ title, description, effects[], durationDays, appliedAtDay }`；
  `durationDays: -1` = 永久，仅 AI 可移除（裁定 §8-1）。
- **同名即刷新**（裁定 §8-10）：同地块同 title 再次下发 = 整条覆盖（描述/效果/时长全换、
  到期重算），永久↔限时可互转。幂等吸收 AI 复读，「洪水又持续了 30 天」正是重叙的语义。
- 到期由时间账本自动移除并出系统事件卡；永久状态不参与到期结算。
- **effects 词汇表 v1.2 刻意收窄**（承 ADR-19 语义级、不开任意数值面）：
  - `devProgressPerMonth: ±N` —— 每 30 天对该地块发展度进度 ±N（无发展度的地块上静默无效，
    flavor 照常展示）；
  - 空 effects = 纯 flavor（只进叙事上下文，零机制）。

### F2 发展度（development）

- **只有可通行陆地块**有发展度（裁定 §8-1）；海/湖/不可通行块永远没有发展条与建筑槽。
- 每地块一个发展档（**10 档，档名随包** `developmentLevels[10]`）+ 一条进度条，
  进度值域 −50..100。
- 进度 **≥100 → 升一档、进度清 0**；进度 **≤−50 → 降一档、进度落 50**（裁定 §8-7：
  落 50 给出真实缓冲，衰退是稳步的而不是连锁崩塌）。档 1 进度下钳在 −50（废墟就是废墟，
  不再往下掉档）；档 10 进度上钳在 100（溢出丢弃）。
- **进度只有两种推动者**（裁定 §8-5，零后台模拟）：
  ① 地块状态的 `devProgressPerMonth` 周期效果；② 一次性 op `tile_dev_progress_add`
  （「玩家重建了水渠，+20」这类瞬时叙事时刻）。没人叙述的地块永远不变。
- 各地块**起始档**编译期烘进 pack（`tiles[].development`）；进度条是每存档事实。

### F3 建筑槽（building slots）

- **槽数 = 当前发展档数**（档 1..10 ↔ 槽 1..10，天然满足 min 1 / max 10，无独立字段）。
- **严格槽位身份**（裁定 §8-8）：建筑住在编号槽位里；降档**永远移除最高号槽**并摧毁
  其中的建筑 —— 空槽也移除、玩家产业也不豁免，摧毁必出系统事件卡。
- 新建筑自动落入**最小空槽**（老建筑天然住在更安全的低位槽）；v1.2 不做槽间搬迁。
- 建筑记录：`{ name, description?, ownerFlavor, playerOwned, income? }`；
  name 是该地块内的逻辑键。

### F4 建筑所有权（ownership）

- **默认纯 flavor**：`ownerFlavor` 自由文本（「市长」「铁匠公会」），与地块 `countryId`
  叠加供 AI 叙事。不机制化、无易手模拟。
- **`playerOwned: true` 才有真实效果**（裁定 §8-9：所有权翻转只经叙事 op，无直买按钮）：
  v1.2 仅金钱收益 `income: { amount, periodDays: 30, anchorDay }`，按期入账
  **玩家角色的 `money`（G）** —— 金额由 AI 在授予时写定，走既有 delta patch 路径
  （与 EXP 奖励同形状）。
- 建筑来源只有两条（裁定 §8-9）：pack 初始建筑（编辑器创作、verify 校验 ≤ 起始槽数）
  与运行期 AI op。

### F4b 主建筑（main building，2026-08-18 追加裁定 §8-17~19）

- **每个可通行陆地块恰有一座主建筑**，代表该地块的主聚落。**独立字段、不占编号槽**，
  **降档免疫**（城镇缩水时市政厅不消失，只是管得更少）—— 槽位建筑契约（§8-8）原封不动。
- **命名**：pack 可逐块作者命名（`MapTile.mainBuilding`，编辑器创作，如「银帆城城堡」）；
  未命名地块按**当前发展档**从 pack 的 10 项档位通名表（`mainBuildingNames[10]`，
  与 `developmentLevels` 并排随包）派生通名 —— 派生名随升降档自然变化；
  作者名或 AI 改名一经落定即钉住不再随档变。AI 改名/改归属走 op，记入编年史（带 reason）。
- **所有权语义与槽位建筑完全一致**（BuildingRecord）：默认 `ownerFlavor`（「领主」），
  叙事可授予玩家（取得记 `acquired` 编年史条目）、可带收益 —— 王冠级产业，
  除降档免疫外一切如常。**不可被摧毁、不可被移除**（update 是唯一写面）。
- op 寻址：主建筑名会随档漂移，故 `tile_building_update` 以 `main: true` 寻址主建筑，
  不按名字（名字寻址只用于槽位建筑）。

### F5 地块编年史（tile history）

- **五类自动事件**（裁定 §8-14），全部由 Code 在既有 op/结算路径旁观记录，带游戏内日期：
  建筑落成 / 建筑被毁 / 玩家首次到访 / 升档 / 降档（+第六类：玩家取得产业并入建筑事件记录）。
  状态挂/除**刻意不记**（同名刷新会刷屏）。
- **AI 富化通道**（裁定 §8-15）：① 每个 AI 发起的地块 op 带可选 `reason`，落进对应
  自动条目；② Code 侧结算引发的摧毁自动引用当时在场的负面状态（「毁于地块衰退（洪水）」）；
  ③ 第六个 op `tile_history_note` 允许 AI 事后追加自由文本带日期条目（覆盖「磨坊为何被毁」
  与纯 lore 时刻）。**自动条目不可编辑** —— AI 只加不改。
- **保留策略**（裁定 §8-16）：每地块 FIFO 上限 **10 条**；**首访条目钉住不淘汰**
  （FIFO 只作用于其余 9 格）。UI 地块详情展示全部保留条目；MAP_CONTEXT 只带
  **当前地块**最近 3–5 条的单行标题（邻接块不带）。
- 🔴 **自动条目存结构化数据不存中文**（kind + 参数：建筑名/起落档位/状态名），中文措辞
  在 placeholder-registry 与 UI 渲染 —— 引擎 `map-*.ts` 零中文字面量闸门照旧成立。
  AI 的 note/reason 是 AI 产的内容，原文存储不受此限。

## 2. 写侧通道：dispatcher 六个新语义 op（对 ADR-026 的收窄改判）

v1 铁则「不给任何 agent `map_*` 写工具」在 v1.2 **收窄改判**（裁定 §8-3）：
owner / terrain / adjacency / impassable 依旧**不存在任何写 op**（v1 保护面原封不动）；
新开的写面只覆盖「叙事产生的事实」，通道走 request_dispatcher 的 StatePatch 管线
（不新开 Agent、不加标记协议）：

| op                      | 语义                                                       | 寻址                |
| ----------------------- | ---------------------------------------------------------- | ------------------- |
| `tile_status_add`       | 挂状态（title/desc/effects/durationDays + reason?）        | **地块名**（非 id） |
| `tile_status_remove`    | 移除状态（含永久状态的唯一出口）                           | 地块名 + title      |
| `tile_building_add`     | 记一座建筑（ownerFlavor / playerOwned / income + reason?） | 地块名              |
| `tile_building_update`  | 改建筑归属/描述/收益（玩家取得产业走这条 + reason?）       | 地块名 + 建筑名     |
| `tile_dev_progress_add` | 一次性发展度进度 ±N（+ reason?）                           | 地块名              |
| `tile_history_note`     | 追加一条自由文本编年史条目                                 | 地块名              |

- 承数据字段规范铁律：**逻辑键 = 名字，AI 永不产 id**；地块名经精确解析
  （原文相等 → 归一化相等 → 放弃），解析失败 warn 忽略、**不打断正文提交**
  （照 v1 §12-4「被动解析不否决」口径）。
- 读侧先行（「只教不管」）：AI 会正确使用这些 op 的前提是 MAP_CONTEXT 持续展示现状（§5）。
- dispatcher 模板加教学段：什么时机下 op、按名字写、拿不准就不下。

## 3. 存储与自愈边界（ADR-33 的核心）

- **新增 `worldFlags.mapFacts` 命名空间**（状态/发展度/建筑/编年史四类事实），照
  **ADR-32 `worldFlags.randomEvents` 先例**：**事实不是派生态** —— 没有 packStamp 清空、
  零新 Dexie 表、随 saveProfiles 进 FullBackup（裁定 §8-4）。
- 现有 `worldFlags.map`（lastTileId / journey / 天气）保持派生态语义**不变**（换包仍清空
  重落位）。**两个命名空间的自愈语义相反是设计出来的，不是不一致。**
- 事实以**地块名**为键（读取时解析到地块）：换包后名字仍在 → 事实继续生效；名字消失 →
  **休眠不删**（承内容包三态语义），包回来自动复活。**休眠地块不结算**（不到期、不入账 ——
  时间对休眠块冻结）。
- **copy-on-write 播种**：某地块的事实条目在**首次偏离 pack 基线时**创建（含首访记档），
  以当时的 pack 基线（起始档 + 初始建筑）为种子；此后事实为权威 —— 被毁的初始建筑不会
  复活，pack 更新也不会给旧档追加初始建筑。有效视图 = 有事实条目取事实，否则取 pack 基线。

## 4. 时间账本（TimeLedger）

**回合驱动，不是自走时钟**（裁定 §8-2）。游戏时间只在提交时经 `delta_time` 前进
（AI 权威不 clamp），无后台 tick 需求；真实时钟会毁掉全仓种子化确定性。

- 形态：`time-ledger.ts` 纯函数模块（**不叫 map-\***，放引擎公共层）+ state-manager
  提交作用域内**一个**统一钩子 `onGameTimeAdvanced(prevMinute, nextMinute)`。
- **零簿记调度**：不存 ledger 状态 —— 到期点从事实里的锚（`appliedAtDay` / `anchorDay`）
  纯推导：`欠账期数 = floor((now − anchor)/period) − floor((prev − anchor)/period)`。
  同参数重放天然一致，无 lastSettled 字段可漂移。
- **每事实独立 30 天锚 + 完整补结算**（裁定 §8-11）：一次 `delta_time` 跨 90 天就按序
  结算 3 个到期点（收益三笔、周期效果三次，途中可跨档触发降档摧毁），带迭代上限护栏。
- **集中调度、分散结算**：账本只算「谁到期了」，结算回调归各系统。天气跨天重断言与
  随机事件逐天掷骰**本次不迁**（已实施、已测试、部分待真机），只保证钩子接口容得下它们；
  新功能一律走账本，不许再自己摸时间。

## 5. 读侧（AI 与玩家看到什么）

**MAP_CONTEXT（dispatcher）与 `$map`（story 世界书 EJS）**（裁定 §8-12「本块全量、
邻块标题」）：

- 当前地块：全量 —— 档名 + 进度、每条活跃状态（标题/描述/剩余天数或「永久」）、
  建筑列表（名字/归属/玩家产业标记）+ 空槽数、编年史最近 3–5 条单行标题。
- 邻接地块：每块一行 —— 档名 + 活跃状态**标题**（无描述、无建筑、无编年史）。
- 缺席状态零 token（照既有 MAP_CONTEXT 口径）。
- 中文措辞全部在 placeholder-registry（dispatcher 面）与内容仓世界书条目（story 面）；
  `$map` 扩展只产 ASCII 键结构数据。

**UI**（裁定 §8-13，v1.2 只做核心面）：

- 势力地图页签的**地块详情**扩展：发展条 + 档名徽章、状态列表（倒计时/永久徽章）、
  建筑槽格（空槽/建筑卡/玩家产业高亮）、编年史列表。
- **系统事件卡**四类提示：状态到期 / 升降档 / 建筑被毁 / 收益入账。
- 视图染色模式、玩家产业清单页、HUD 状态条 —— 全部推迟。

## 7. 明确不做（v1.2 非目标）

- 发展度影响寻路 / 税收 / 国家 AI 模拟（发展度的机制面 = 槽位，仅此一条）。
- 建筑玩法（建造成本 / 升级树 / 生产链）—— 建筑是叙事记录，不是经营系统。
- NPC 所有权机制化（仍 flavor）；建筑收益的非金钱形态；直买按钮。
- 天气 / 随机事件迁入时间账本（只留接口）。
- 视图染色 / 产业清单 / HUD 状态条（UI 推迟项）。
- 编年史条目编辑（AI 只加不改）。
