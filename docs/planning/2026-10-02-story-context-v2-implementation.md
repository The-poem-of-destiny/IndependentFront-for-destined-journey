## 已确认产品规则与临时实现边界

第 2 区保留全部长期记忆总览；第 3 区按地理区域定义；N>0；第 5 区召回详情，暂不与第 2 区去重；事件结束包括成功完成、放弃和失败。
预设已确认五个不可删除分区占位条目、1→5 相对顺序、中间可插入普通条目及按模式填充的规则。普通条目的消息角色、旧上下文占位符适配和既有预设补入位置仍需实际核对；内容包与条目路由待详细核对。每回合摘要、双层归档产物、两步召回、两种原文粒度及第 4 区与召回的关系已确认；事件关联与结束判断、物理存储、召回执行职责、粒度使用策略和失败处理细节后续讨论。下文保留相关实现建议，不表示这些技术细节已经冻结。

## 上下文顺序

1. 第 1 区（固定前缀）：固定指令与必要世界资料；普通预设条目可穿插在分区之间。
2. 第 2 区：全部长期记忆总览，包含事件总结与已结束事件记录，类似历史年表。
3. 第 3 区：当前地区的地理、势力等非频繁资料，采用偏地理区域的定义。
4. 第 4 区：窗口外的全部未归档摘要，随后是最近 N 轮完整玩家输入与 Story 正文。
5. 第 5 区：当前人物、场景资料、召回的记忆详情及其原始正文、当前事实；本轮玩家输入位于最末。

第 2 区不按当前话题筛选，正常推进时只在新事件结束并触发记忆归档后更新，不因普通回合或重要事实变化单独更新。
第 2 区提供概括，第 5 区提供具体详情，暂不做两区之间的去重。

N 必须为正整数（N>0），不允许 N=0。运行时与 Story v2 设置端一致；旧模式/其他 Agent 保留原历史层数语义。沿用用户接受的存储口径：Story 的「历史注入层数」，未设置默认 6；默认值不是经真实回合评测后的正式效果策略。
此模式不截断窗口内正文，不使用 Delta transcript。摘要没有单独的数量上限。
渲染结果按作者指定的分区注入；依赖每轮状态的 EJS 条目应标为 turn。未选中的条目不执行 EJS。

## 预设兼容与消息装配

预设中强制存在 5 个不可删除的分区占位条目，对应以上五区；相对顺序必须保持 1→5，允许在中间插入普通预设条目。装配时遍历预设，在对应占位位置加入引擎已组装好的该区消息，并保留普通条目的穿插位置。

- 开启实验性上下文时，五个区域激活并填入对应内容。
- 未开启时，五个条目仍存在但展开为空，不生成空白 API 消息，不触发新分区任务；普通条目与旧上下文继续按原有方式装配。
- 五个分区不等于五条 API 消息。第 4 区完整历史保留真实 user／assistant 角色，不能把各区重新压成单条 system 文本；本轮玩家输入仍位于最末。
- 旧历史、世界书、记忆占位符不得全局删除或停用。仅在实验模式适配旧入口，避免与五区重复注入；保留有效指令，不进行第 2 区概括与第 5 区详情之间的去重。
- 创建、导入、编辑、更新和重置应保持五区条目存在及顺序约束；条目标识、缺失条目补入位置、普通条目的消息角色与旧入口映射待 Story P0／内容 C0 对齐。

三种协议验收时按实际请求体检查角色、分区与普通条目顺序，以及旧入口与新分区的重复注入。当前 Claude／Gemini 适配器限制对话中途的 system 消息，普通条目的角色映射仍需讨论，不能用移动作者条目位置规避问题。

归档产生事件详细记录与概括记录已确认；长期总览的生成实现、物理存储、长度与超限处理仍待讨论；预算统计需单列第 2 区，不擅自按本轮话题裁剪总览。
配置了模型上下文窗口时，按分区估算 tokens，并使用端点请求体覆盖／省略之后的输出预留。
预算优先减少可选资料和召回，不裁剪必需摘要或正文。可选资料在 EJS 求值前按原文估算筛减，
相互依赖的条目作为同一预算单元；每个保留条目只求值一次，再按渲染结果检查最终预算。
若 EJS 扩张或必需内容仍超限，报出各分区用量并停止 Story 请求。估算不是 provider 实测 usage；
未配置模型窗口时保留完整内容，不推断模型容量。

资料先按结构化规则激活，再由 `lore_select` 筛选并最多补充三条。该 Agent
使用自身独立配置的端点、模型和参数，只能返回已有条目标识。模型失败时保留必选资料并使用预算内规则候选。
固定、显式必选、命中的地区资料不会被筛选器删除。禁用条目、读取范围和排除词均为硬限制。
依赖闭包也受读取范围与排除词限制。

选择器目录和返回引用只接受 Story 与 lore_select 的 audiences 交集，选择器不执行资料正文
EJS，也不能通过自定义 LORE_BOOK 模板读正文。仅 Story 可读的规则候选由代码确定性保留，
不会向选择器暴露；固定、区域和必选资料的依赖不能被筛选器移除。旧模式同样根据近期对话
和本轮输入执行排除词限制；命中或解除限制时，旧 Delta 的可见资料签名随之变化并重建。

## 记忆生命周期

每个正式完成回合生成摘要，即使原文仍在 N 窗口内。摘要保存行动、结果、关键约定、关系变化与未解决事项；允许按事件分段，不强制将所有闲聊归入事件。
原文在窗口内时只注入完整原文，移出窗口后由已有的未归档摘要承接。`memory_summary` 仍作为摘要执行者的实现基线，跨回合事件关联及结束判定机制待讨论。
事件结束时触发归档，包括成功完成、放弃和失败，并更新第 2 区全部长期记忆总览。
归档需提供事件结束证据；此前提出的“本轮正文逐字证据”作为待后续记忆讨论核对的实现建议保留。
归档同时产生事件详细记录与第 2 区概括记录。详细记录保存起因、关键经过、结局、重要约定、持续影响和来源原文关联；概括记录用较短文字记下事件在长期经历中的位置与结果，纳入全部长期总览。
两层产物不预先要求两次模型调用或两张独立数据表。归档记录覆盖的摘要关系；成功后对应摘要退出常驻范围，但原摘要、详细记录与原文仍保留可检索，未结束事件继续保留。
第 4 区的摘要部分只展示未被有效归档覆盖、且位于正文窗口外的摘要；窗口内保留完整原文。
召回根据本轮输入、场景、人物和近期对话，先检索摘要或事件详细记录定位相关经历，再读取所需详情，补充常驻上下文没有充分提供的信息。涉及准确措辞、约定、数字和关键因果时，沿来源关联读取真实原文，结果进入第 5 区。
第 4 区窗口外未归档摘要全量常驻，不按召回相关性筛选；召回不改变归档状态，不改变第 4 区范围，也不让旧原文占用最近 N 轮的名额。
源消息已被回滚移除的记忆不参与上下文。回退到某次归档之前时，第 2 区恢复到上一个有效归档节点；若此前没有归档，则恢复为尚无归档总览的状态。
失效归档不再覆盖其来源，回退后仍有效的相关正文与摘要恢复未归档语义，并按 N 窗口展示；不恢复已被回退移除的未来内容。
归档失败时保持上一有效总览与未归档摘要。

已实现的归档方式（Q13 裁定 + Q12 自选）：

- 每轮的总结 Agent 先对照本轮开始时的未结事件做归档判断，再写本回合摘要。跨回合的同一事件靠事件名逐字一致关联。
- 代码只接受出自本回合正文的结局依据：去标点空白后子串命中，或字二元覆盖率不低于 0.6（容忍改写措辞）。被拦下的事件保持未归档并提示。
- 归档通过后，用事件涉及的每个回合的玩家输入与正文原文另行生成详细记录（复用记忆总结 Agent 的端点与模型）；失败时保留总结 Agent 的简要版本，并在记忆面板标明来源。
- 归档记录（Dexie v28 `storyArchives`）同时保存概括与详细记录、覆盖的摘要片段 id、作出判断的回合消息 id。
- 第 2 区就是当前分支上有效归档的年表；回退删掉判断回合后，归档失效、第 2 区退回上一节点、被覆盖的摘要恢复常驻。
- 归档提交失败保存原判断回合与原摘要草稿，后续有界自动重试，使用原结局证据；成功删除草稿，来源或覆盖修订后失效。详情生成失败保留标为据摘要的版本并重试原文详情，不要求下一轮重复结局。
  配置了 embedding 端点时，为新摘要和归档生成向量；生成失败保留文本记录。

## 原文召回粒度与待定机制

同时纳入以下两种方案，后续用相同查询和来源进行测试：

- 完整回合：读取对应完整玩家输入与 Story 正文。
- 片段加前后文：读取相关原文片段及必要上下文。

比较信息完整性、准确性、叙事效果与消耗后，再决定使用策略；本轮不预先增加玩家开关或确定由模型自动选择。片段边界与前后文范围也随测试细化。

第五批的实现（复用现有记忆召回，见 `src/core/memory/story-recall.ts`）：

- 候选：当前分支上的有效归档（A1…），加上来源在正文窗口外的有效摘要片段（S1…，含已归档片段）。窗口内回合的原文已在第 4 区，不作为候选。
- 定位：模式沿用 设置 → 记忆。
  - LLM：召回 Agent 读编号清单、当前时空、角色状态、最近对话与本轮输入，只返回编号。
  - Embedding：查询为本轮输入加上一回合摘录，可选重排。
- 展开：选中的摘要、事件详细记录与来源原文进入第 5 区「相关回忆」，也供剧情前置检查读取（v2 管线先跑召回，前置检查显式等它）。
- 原文粒度：开发者模式卡片中的「召回原文粒度」切换整回合或相关片段。片段取最相关的段落加前后各一段。
- 临时规则：原文总量上限 12000 字，超出的回合只保留摘要并标注省略；窗口内回合写明「原文在最近对话中」，不重复贴出；同一回合原文只贴一次。
- 失败：召回失败时输出空串并提示，前置检查与 Story 照常运行。

Q15 本轮按用户裁定更新：摘要失败交给补建，非法归档判断不生效，有效判断的失败草稿绑定原回合重试；召回失败输出空串并提示、不阻断 Story。仍待真实效果/费用比较确定两种原文粒度的正式默认及是否按需读原文（第一版选中即附原文）；同回合多片段按全部选择结果合并，不因候选顺序丢失。Embedding 仅帮助定位，不能替代事件判断与原文读取。
