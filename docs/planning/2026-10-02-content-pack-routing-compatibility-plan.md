[Story 上下文与记忆计划](2026-09-30-story-context-memory-content-routing-plan.md)负责模式开关、资料选择 Agent 的运行、上下文组装、三层记忆和测试存档隔离。内容包兼容两种方案不表示两种方案的存档或记忆格式互通。

2026-10-04 消费侧确认：Story 第 2 区保留全部长期记忆总览，类似历史年表，仅在新事件结束并归档时更新；事件结束包括成功完成、放弃与失败。第 3 区采用地理区域定义，正文窗口 N>0，第 5 区召回具体详情且暂不与第 2 区去重。长期总览来自存档记忆，不由世界书条目生成或内容包更新触发；其归档节点和回退行为归 Story 计划负责。

讨论边界：本计划保留现有内容包、条目拆分与读取范围方案，下一步需进一步详细说明与核对，本轮不扩展字段或路由能力。预设已确认强制保留五个不可删除分区条目，相对顺序 1→5，中间可插普通条目，实验模式填入消息、旧模式展开为空；普通条目消息角色及旧占位符适配仍待讨论。每回合摘要、事件详细记录与第 2 区概括记录两层归档产物、先定位后读详情的召回流程，以及完整回合／片段加前后文两种原文方案已由 Story 计划确认；第 4 区常驻范围不受召回筛选影响。这些内容由存档记忆侧实现，不增加内容包条目职责。事件关联、物理存储、召回执行与失败处理等细节仍由 Story 计划后续讨论。

| 条目更细                  | 保留原始资料，按地理、角色、规则、活动和协议等用途拆分，维护稳定身份             |
| 由内容决定 Agent 可读范围 | 构建时写入 lore.audiences；两个方案均使用该范围，不再读取玩家逐 Agent 世界书清单 |

| 兼容旧方案                | 提供旧读取接口可消费的数据，保留必要正文、旧占位符与记忆输出契约                 |

| 存档边界                  | 更新内容不标记普通档为测试档，不转换历史或记忆；测试档仍禁止在旧模式使用         |

## 3 条目模型与识别协议

### 3.1 条目身份与读取标识

条目身份回答“是哪一条资料”，读取标识回答“哪些 Agent 可以读取”。两者独立，且都细化到每一个条目：稳定条目键与 audiences 均由条目自身声明、逐条生效，不按类别、分类或来源批量设定。

建议为 WorldBookEntry 增加 lore 元数据，具体类型在 C0 冻结：

| 元数据         | 职责                                                             |
| -------------- | ---------------------------------------------------------------- |
| 稳定条目键     | 带来源命名空间，支持检索、依赖、更新及拆分；与显示名称分离       |
| audiences      | 明确列出允许读取的 Agent ID，例如 story、char_gen                |
| 内容类别       | 世界规则、地理、人物、种族、组织、产业、协议等                   |
| Story 放置策略 | 固定、区域、本轮；只控制 Story 分区，不代替其他 Agent 的读取范围 |
| 激活规则       | 声明当前哪些事实、话题或行为使条目必选或成为候选                 |
| 依赖条目       | 当前条目需要的最小背景资料                                       |
| 检索摘要与别名 | 帮助选择 Agent 检索，不替代最终注入正文                          |
| 来源关系       | 上游条目、旧 UID、拆分位置及必要的内容修订信息                   |
| 顺序与优先级   | 确定稳定渲染顺序和候选预算分配                                   |

沿用现有生产 UID 对账，不按显示顺序、运行时模糊名称匹配或每次构建生成的随机值重建身份。细分条目分配稳定子身份，并记录父来源。没有拆分的条目尽量保留原身份。

内容元数据与所有新类型集中在 types.ts 或对应 types 分册。AI 只选择已提供的条目引用、填写语义判断，不生成存档 ID、数据库主键或账务字段。对 AI 展示的检索引用需要与物理主键分离，并在 C0 与数据字典规则对齐。

### 3.2 唯一读取入口

公共读取层先确定可用内容与 Agent 范围，再交给对应方案的消费者。下列完整选择流程供新方案使用，旧方案的适配见第 5 节：

```text
来源可用且内容已启用
  → 当前 Agent 命中 lore.audiences
  → 满足硬性适用条件
  → 区分固定项、必选项与候选项
  → 候选筛选和允许范围内的补充
  → 依赖校验与去重
  → 正文渲染
```

audiences 不匹配的条目不能通过手写模板、EJS 间接展开、依赖引用、工具读取、Delta 或检索补充绕过限制。依赖关系不授予额外读取权限；生成端应发现这类依赖与读取范围矛盾。

玩家可以继续使用已有内容包或 DLC 的启用机制，但 Agent 配置页面不提供逐 Agent 书列表、开关或 audiences 编辑。内容作者在生成端维护声明。

### 3.3 分类与粒度

“本体／DLC”表示来源或启用方式，不直接决定注入位置。“势力”目录同时包含国家、文化、城市与场所，不宜作为唯一激活类别。分类用于组织、检索与生成初始建议，不直接等于读取范围；audiences、分区与硬条件等路由字段按条目维护、逐条复核，不复用类别默认值。

首批分类覆盖：

- 全局必要世界规则与固定叙事规范。
- 地理、城市、城区、具体场所。
- 人物、种族与相关组织。
- 政治、文化、节庆及专题背景。
- 交易、旅行、制作、产业和冒险活动。
- 面向执行或生成 Agent 的协议资料。

世界规则正文也要检查粒度：全局必要约束可常驻，专项数值表、远方地区条例与执行协议按用途拆开。大型地下城条目应评估按区块或楼层拆分。有效规则不能因为条目名称像组织标记就删除。

拆分以原文边界和明确映射为依据，保留原始语料，不通过自动改写制造新的世界设定。

## 4 结构化激活规则

### 4.1 规则规划与第一版支持面

本轮用户明确裁定：第一版只实现当前位置（按**包含**命中，2026-10-10 裁定放宽，原为「完整层级逐字相等」）、在场人物、关键词与硬排除关键词；正向条件按 OR 匹配，排除词优先，两种模式共用硬限制与依赖判据。不支持任意表达式。下表保留长期规则规划，不表示任务/剧情、行为场景、时间及显式组合已经实现；这些扩展正式移至后续，不作为本轮未补齐协议。

| 条件                   | 用途                         | 注意事项                                                                                                                               |
| ---------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 当前位置与所属区域     | 本地背景、具体场所           | 采用内容声明的标准名称或引用；资料路由按**包含**命中：玩家路径任一层级包含声明字串（地图「不模糊匹配」契约约束的是落位，不是资料路由） |
| 当前在场人物           | 人物必要设定与种族依赖       | “常活动于某地”仅为候选线索，不能证明当前在场                                                                                           |
| 当前输入与近期对话提及 | 异地、人名、组织、物品或话题 | 搜索范围有限，不因几百轮前提及而永久激活                                                                                               |
| 任务与剧情状态         | 当前事件背景                 | 读取既有事实，激活器不推进任务或主线                                                                                                   |
| 行为与场景类型         | 交易、旅行、制作、战斗等     | 区分玩家表达的意图与实际发生的事件                                                                                                     |
| 时间与地区             | 当地节庆或时间条件           | 日期从游戏时间读取                                                                                                                     |
| 依赖关系               | 术语、种族、最小上级背景     | 不自动展开所有兄弟或父级全文                                                                                                           |
| 条件组合               | 全部满足、任一满足、排除     | 第一版使用小型声明式规则，不执行任意 JS                                                                                                |

规则由内容包提供，引擎只执行通用判定，不硬编码具体城市、种族和角色名称。

### 4.2 必选与候选

以下为新 Story 消费这些规则的语义；内容包声明规则，选择 Agent 的调用与分区组装归 Story 计划负责。旧方案不因增加这些声明而强制采用新分区或筛选器。

- 固定资料按其声明进入顶部。
- 当前场景必须遵守的约束及必需背景属于必选，选择 Agent 无权删除。
- 宽松匹配和语义关联产生候选，由 Agent 进一步筛选。
- 禁用、audiences 不匹配或违反硬条件的条目不进入补充范围。
- 仅不满足软相关性条件的条目仍可通过有限补充找到。

“激活”表示向 Story 提供参考，不表示必须安排人物登场、触发事件或公开秘密。人物可见的知识、导演信息与事实揭示继续使用各自协议。

### 4.3 依赖与异常

构建端校验不存在的引用、重复身份和循环依赖。运行时按稳定条目键去重；内容更新使依赖不可用时输出明确诊断，不借机扩大权限或注入整本书。

条目补充、依赖展开和最终正文注入共享同一可读范围。用户明确停用的内容不因依赖被偷偷重新启用。

## 5 同一内容包的双方案兼容

### 5.1 共享内容层与消费适配

建议沿用一个规范化条目模型和公共读取器，仅在消费接口处适配两种方案，避免维护两份互相偏离的正文或包产物。

```text
同一内容包
  → 校验与规范化条目
  → 启用状态、audiences、硬性限制、依赖校验
  ├─ 旧方案适配 → 既有资料展开与提示词接口 → 原上下文、Delta 与记忆流程
  └─ 新方案消费 → 固定／区域／本轮候选 → lore_select → 分区上下文与新记忆流程
```

| 项目                      | 旧方案                                                                  | 新测试方案                                 |
| ------------------------- | ----------------------------------------------------------------------- | ------------------------------------------ |
| 条目身份、正文、audiences | 使用共享数据                                                            | 使用同一共享数据                           |
| 返回形状                  | 适配既有 WorldBook／WorldBookEntry 或正文接口，保留调用方必要字段与顺序 | 返回条目引用、正文、分区、规则与依赖信息   |
| 资料激活                  | 保留旧消费者必要的确定性启用与展开语义；不要求调用新 Agent              | 按结构化规则生成必选与候选，进一步筛选补充 |
| section 等分区声明        | 不因无法识别新分区而丢弃正文                                            | 决定固定、区域和本轮位置                   |
| lore_select               | 不调用，不作为旧模式成功运行的前提                                      | 由 Story 新模式编排调用                    |
| 摘要与归档                | 保留旧 memory_summary 输入输出和原处理器                                | 使用新摘要、阶段归档的契约与处理器         |
| 预设与占位符              | 原有调用契约继续有效，资料读取范围改由 audiences 决定                   | 按新上下文职责展开，避免重复注入           |
| 缓存                      | 内容变化使旧方案相应内容签名失效                                        | 内容变化使新方案区域与选择缓存失效         |
| 存档                      | 普通档继续可用，不自动升级                                              | 只使用带测试标记的存档                     |

这里保留的是旧上下文与记忆消费方式，不恢复已退役的 worldBookIds 权限配置。旧消费者需要按书组织数据时，可以保留来源分组和稳定顺序，但分组不得扩大 audiences 允许的条目集合。

### 5.2 激活与拆分的兼容要求

- 明确区分硬性禁用／排除、软相关性候选与新 Story 分区提示。两种方案都遵守硬限制；旧方案不把新方案候选筛选结果或 section 名称当成读取正文的必要条件。
- 新增规则没有旧方案可用的状态字段时，不能把必需世界设定静默判为不可读。C0 为相关规则定义明确的旧方案适配，并用代表性语料验证；不支持的硬条件必须诊断，不能借兼容放开权限。
- 拆分后旧方案仍可通过现有读取接口得到完整的必要规则与资料；按父来源和作者顺序展开，不同时注入父正文与子正文。
- EJS 正文不自动切割。保留调用所需运行时和求值语义，避免拆分导致重复副作用或丢失上下文。
- 条目作者需要让资料同时可供 Story 与 lore_select 使用时，明确声明两者；选择器可传给 Story 的集合仍与 Story 可读范围取交集。
- 内容包更新不得以清空玩家历史、旧记忆、存档或全部预设来实现兼容。

### 5.3 默认 Agent 配置与预设

内容包不只包含世界书。默认预设、Agent 配置、提示词与输出协议也必须纳入两种方案兼容验收。Story 预设采用五个不可删除的分区占位条目：相对顺序固定为 1→5，中间允许插入普通预设条目。实验模式将各区已组装消息加入对应位置；旧模式保留这些条目但展开为空，不生成空白消息，继续旧上下文装配。具体分区职责与运行流程以 Story 计划第 3.1.1 节为准。

1. 旧 memory_summary 的提示词与输出格式不能被新分段摘要／归档格式全局覆盖，否则旧处理器会收到不兼容数据。
2. 五区占位条目在两种模式的预设中都存在，仅新模式填入内容；lore_select 与新归档指令只在新模式调用中使用。旧流程不能因缺少新调用上下文而渲染失败，也不能为填充空占位调用新模块。
3. 建议保留共享配置，在现有配置机制中增加必要的新模式覆盖；如现有机制不支持，提供最小的模式专用预设引用。C0 决定具体字段，不为此设计通用多版本配置平台。
4. Agent 更新中心、重置与默认值合并都必须保留两个方案对应的契约。去掉世界书选择字段不能顺带清除模型、端点、用户提示词或其他设置。
5. 同一包可以包含两种模式需要的指令资源，但只有一份资料正文与稳定身份；用户切换 Story 模式不需要重新安装内容包。
6. 旧历史、世界书、记忆等上下文占位符继续服务旧模式，不全局删除或停用；实验模式适配旧入口以避免与五区重复注入，保留普通条目中的有效指令。
7. 默认预设、导入、更新和重置需维持五区存在与 1→5 的顺序，不覆盖作者插在分区之间的普通条目。占位身份与缺失条目补入位置在 C0 与 Story P0 对齐；普通条目的消息角色及旧入口映射仍待实际预设核对。

## 6 生成工具与条目编排

### 6.1 作者侧声明

在内容组合工具中维护可审查的条目路由声明，构建产物写入所需识别符，不依靠运行时书名猜测。批量分类只作为初始建议；生产 audiences、分区及硬条件必须逐条复核。

先验证一个城市及子区域、一名有种族依赖的人物、一组活动条目和一个大型混合条目，再扩展到完整内容。固定规则、区域背景、本轮资料、执行 Agent 专用协议都需要代表样本。

### 6.2 导入与拆分

- 保留原卡到生产 UID 的对账及原始语料。
- 子条目使用作者维护的稳定身份、正文边界和父来源；再次导入不覆盖已经编辑的路由声明。
- 构建只输出生效的细分条目；父项如仅作组织来源，不再重复注入完整正文。
- 出具拆分和身份映射报告，覆盖改名、排序、重复构建与条目删除。
- 旧消费者所需的来源分组和稳定渲染顺序在构建结果中可恢复。

### 6.3 构建检查

校验唯一身份、合法 Agent ID、audiences、类别、规则字段、分区值、有效引用、依赖循环及父子重复正文。语法通过还需检查必需世界规则没有因拆分、硬条件或错误读取范围而丢失。

构建同时检查旧模式必需预设和新模式所需资源。用于新模式的额外配置不能改变旧模式输出契约；占位内容和私有真实内容遵守相同字段定义。

### 6.4 既有实验摘要中的接口候选

原实验模式摘要中的内容编排细节移入本节保留，作为 C0 核对与冻结的输入，不表示对应代码已经实现：

- 私有内容仓可使用 tools/lore-routing.mjs 维护初始分类和构建检查。
- 条目字段包括 lore.key、audiences、section、required、summary、dependsOn，以及 activation.locations／characters／keywords／excludeKeywords。
- 简单激活形式采用正向条件 OR、排除词优先；位置按**包含**判定——玩家位置路径的任一层级包含声明字串即命中（2026-10-10 裁定放宽，原为「完整层级逐字相等」）。若采用第 4 节的显式组合规则，必须定义两者的转换或优先关系，不能让生成端与读取器各自解释。
- 作者通过 parts 显式拆分大条目。每个子项提供永久 uid、name、content 和 lore.key，其他元数据可继承父项；继承结果在构建时校验，子项读取范围仍以最终 audiences 为准。
- 构建只输出子项，不自动切割 EJS 或正文；角色卡重新导入按稳定 uid 保留已经编辑的路由信息。
- 依赖本轮状态的 EJS 条目可声明为 turn；此分区语义由新方案消费，旧方案保持原有正确求值时机，不因为新增标记而丢弃条目。

这些字段与规则同样需要通过第 5 节的旧消费者兼容检查，不能只验证新方案能够解析。

## 7 内容生命周期与页面改造

### 7.1 安装与更新

- 内容包声明可识别的新协议修订及最低引擎兼容要求，具体版本号在实施时确定。
- 内容包构建、导入、更新和读取统一切换到新协议，不读取实验开关，也不维护两套内容包运行模式。
- 生成端保存拆分前后映射，安装、更新和卸载流程保留条目身份及必要的用户内容修改语义。
- 读取范围逐条目声明；书级 `audiences` 与旧包兼容映射（含玩家旧 worldBookIds）均已移除，不再据此决定权限。
- 未带识别符、来源未知的第三方条目不能默认对所有 Agent 开放。具体停用与诊断体验见 CQ01。
- 工坊条目、占位资料、overlay 加载、原生内容包导入必须使用同一契约。
- 内容构建保存条目身份与拆分来源映射。拆分造成普通档或测试档中的内容启用引用变化时，只对内容引用做明确映射，保留原启用语义；不改写消息、记忆格式或测试档标记。不能用“不兼容新旧存档”免除新版内容包服务普通档的责任。
- 审查固定书数量和 Agent 数量断言。新增 lore_select 的注册和默认资料可以随包提供，但只有新方案调用它；默认预设与输出契约按第 5 节保留旧方案能力。

### 7.2 Agent 世界书设置退役

删除页面控件后继续清理 AgentSettingsEntry、默认配置类型、覆写合并、旧字段迁移、重置入口、更新中心、导入导出以及指纹生成器中的 Agent 世界书配置。

旧配置即使仍存在于历史备份中，也不参与运行时路由。Agent 的模型、参数、提示词和其他非世界书设置按既有行为保留。

美化规则中的 autoEnable.worldBookIds 等同名字段是另一种绑定用途，不在本次 Agent 读取配置退役范围内，禁止全仓按字段名盲删。

### 7.3 调试与更新一致性

调试记录标明运行方案、实际读取条目、audiences、规则结果和适配路径。缺元数据、旧占位符无法展开、依赖不可读或旧方案适配不支持的条件必须可定位到具体条目。

同一包版本在两个方案中使用同一身份、正文修订和启用状态。安装、更新、卸载与 overlay 不得丢弃 lore；跨存档保留各自有效内容启用语义。内容引用调整不改写历史消息或记忆来源，也不移除测试档标记。
