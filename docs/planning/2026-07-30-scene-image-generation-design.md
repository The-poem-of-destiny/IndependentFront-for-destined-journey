## 1. 目标与非目标

### 1.1 一句话

玩家在推进叙事的过程中，正文里该出现画面的地方会**就地长出一张图**——
由叙事 AI 决定画什么、由玩家决定画不画和怎么改、
由引擎负责把这件事做得可重复、可编辑、可回溯。

### 1.2 成功判据

| #   | 判据                                                                                         |
| --- | -------------------------------------------------------------------------------------------- |
| S1  | 玩家在一局 30 分钟的游玩里，可以完全不离开正文区就获得配图；图出现的位置与它所描述的段落对应 |
| S2  | 同一个画位重画任意次，"这张图属于正文哪一句"永远不会错位；刷新、切存档、回退快照后依然正确   |
| S3  | 出图失败**从不打断叙事**；正文照常推进，失败只体现为该画位上的一个可重试按钮                 |
| S4  | 玩家可以改写某一张图的画稿并重画，改写结果在后续重画中保留                                   |
| S5  | 同一套书写语法在能力不同的成像服务下都能出片，差异只体现为**能力降级**而不是报错             |
| S6  | 连续多张配图里，角色的发色/瞳色/服装不会无理由跳变                                           |

### 1.3 非目标（v1 明确不做）

- **不规定具体成像服务的接入细节**。见 §13。
- **不做绘图编辑器**（涂抹、局部重绘的完整交互）。v1 只保留"以某张图为参照图再出一张"这条最小路径，不提供画蒙版的界面。
- **不做动态影像**。端口契约给它留了口子，v1 不实现任何播放面。
- **不做云端图床**。字节一律留在本机。
- **不进 FullBackup**（理由同曲库与素材库：JSON 装不下字节）。迁移路径是导出包。
- **不做工作流可视化编辑器**。模板类服务只接受玩家从外部导出的成品文件。

## 2. 术语表

本系统整体称为**随笔画室**（下文简称"画室"）。术语沿一条统一的比喻：
叙事 AI 负责**取景**，引擎负责**装配画稿**并交给**画师**（成像服务）**出片**，
玩家负责**验稿**与**改稿**。

| 术语                | 含义                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| **取景标记**        | 叙事 AI 写在正文里的一段 XML 标记，声明"此处该有一张画"，携带画面描述            |
| **画位**            | 正文中一处取景标记所对应的呈现位置。一个画位在其生命周期内绑定至多一张**当前稿** |
| **画位号**          | 画位的稳定标识。显式写在正文标记上，不从任何可变字段推算                         |
| **稿次**            | 同一画位上的一次出图尝试及其产物。初稿、次稿、三稿……可翻看、可指定为当前稿       |
| **画稿**            | 交给成像服务的最终词串，分**入画词**与**忌避词**两路                             |
| **入画词 / 忌避词** | 希望出现在画面里的 / 希望排除在画面外的词串（即成像模型所吃的正、负两段提示词）  |
| **画稿装配**        | 从"标记里的原始文字"到"画稿"之间的一串确定性变换（§8）                           |
| **画词典**          | 玩家自定的文本替换表。一个词条把简写（如角色名）展开为一串描述                   |
| **笔法**            | 一组具名的前后置词串与默认参数，用于统一画风（§9）                               |
| **排位语法**        | 在一段描述里同时写多个角色及其画面站位的声明式写法（§10）                        |
| **站位 / 舞台格**   | 排位语法中角色在画面里的位置 / 承载站位的 5×5 网格                               |
| **译稿 Agent**      | 把叙事化的自然语言译成画稿的一次 LLM 调用（§11）                                 |
| **连贯档**          | 结构化记录"当前画面里角色长什么样、穿什么、在哪"，用于跨图一致（§12）            |
| **成像端口**        | 画室与任意成像服务之间的唯一接缝（§13）                                          |
| **成像服务 / 画师** | 端口另一侧的具体实现。本文不规定其形态                                           |
| **能力位**          | 一个成像服务声明自己支持哪些可选能力（区域控制、参照图、模板填格……）             |
| **填格**            | 玩家提供的请求模板中，由画室填入实际值的具名坑位，写作 `{{入画词}}`              |
| **参照图**          | 以既有图片为基底再出一张时所用的那张源图                                         |
| **画室调度**        | 出图任务的排队、冷却、去重、配额（§14）                                          |
| **看图台**          | 全屏查看单张图的浮层                                                             |

## 3. 用户旅程

### J1 · 全自动（默认体验）

玩家输入行动 → 叙事 Agent 产出正文，其中若干处带取景标记 →
正文呈现时这些标记变成**待出片的画位** → 画室按队列逐个出片 → 图就地淡入。
玩家全程没点过任何按钮。

自动出片受配额约束（§14.4）：每轮至多 N 张，超出的画位退化为"待出片"按钮，不自动跑。

### J2 · 手动点亮

自动出片关闭时，取景标记呈现为一个低调的行内按钮。玩家点一下才出片。
适用于按张计费的服务，或玩家只想给关键场面配图。

### J3 · 验稿与改稿

玩家点图 → 打开**验稿面板** → 可见**实际交出去的那份画稿**（入画词 / 忌避词两路）、
全部参数、画师、耗时、随机种 → 就地改写画稿 → "重画"。

改写后的画稿**归属于这个画位**：后续任何重画都用改写版，直到玩家点"还原初稿画稿"。

历史不删：每次重画产生新的稿次，进该画位的稿次列表，可左右翻看、可把任意一稿设为当前稿。

### J4 · 主动取景

玩家在输入框旁点"取景"按钮，手动输入一段描述，或在正文里选中一段文字 →
走译稿 → 出一张图，落在当前消息末尾。
这是唯一一条不依赖叙事 AI 主动写标记的入口。

## 4. 系统分层

```
┌──────────────────────────────────────────────────────────┐
│ L6 呈现        画位组件 / 懒加载 / 看图台 / 验稿面板 / 遮罩  │
├──────────────────────────────────────────────────────────┤
│ L5 调度        串行队列 / 冷却 / 去重 / 自动出片配额         │
├──────────────────────────────────────────────────────────┤
│ L4 成像端口    出片委托契约 ↔ 成片回执契约 ↔ 能力位          │
├──────────────────────────────────────────────────────────┤
│ L3 画稿装配    内联指令 → 画词典 → 排位 → 笔法 → 清洗        │
├──────────────────────────────────────────────────────────┤
│ L2 语义        译稿 Agent / 连贯档                          │
├──────────────────────────────────────────────────────────┤
│ L1 协议        取景标记扫描 / 画位号 / 正文改写事务           │
└──────────────────────────────────────────────────────────┘
```

**单向性铁律**：上层可读下层，下层永不回调上层。
特别地——画稿装配不知道画位存在，成像端口不知道正文存在。跨层只经由具名契约传值。

**与既有子系统的接缝**（都必须是"引擎零改动"式的接入）：

| 既有子系统      | 接入方式                                                                           |
| --------------- | ---------------------------------------------------------------------------------- |
| Marker Protocol | 新增一个标签，进既有标签集，走既有扫描/属性解析/剥离流程                           |
| Agent 编排      | 译稿 Agent 复用既有 ApiEndpoint / AgentConfig / 模板系统                           |
| 管线时序        | 与配乐标记同构：**Stage 1 只暂存，`run()` 末尾状态回读之后才 flush**（§5 第 ② 步） |
| Dexie           | 新增两张表（稿次元数据 + 字节），随存档隔离                                        |
| 素材系统        | 单向出口：一张成片可"存为立绘/头像"，经既有裁剪台落进素材库                        |
| 输出美化        | 取景标记在正文入库前**不剥离**（画位要靠它定位），在美化呈现时替换为画位组件       |

## 5. 一次出图的完整历程

> **本节是全文主干。** 其余章节是对这里某一步的展开，括号里标了去处。

### 5.1 时间轴

```
   叙事 Agent 产出正文
            │
   ① 扫描取景标记 ────────────────────────────── §6
            │  （补齐画位号，正文入库，标记原样保留）
            │
   ② 暂存，等编排流程跑完 ──────────────────────── §5.3
            │  （run() 末尾、状态回读之后才继续）
            │
   ③ 画位建立 + 命中既有稿次？ ─────────────────── §7
            │        ├─ 命中 ──▶ 直接呈现，结束
            │        └─ 未命中 ─▶ 继续
            │
   ④ 入队（自动出片配额 / 手动点击）─────────────── §14
            │
   ⑤ 取连贯档 ────────────────────────────────── §12
            │
   ⑥ 译稿（自然语言 → 画稿；可跳过、可批量合并）──── §11
            │
   ⑦ 画稿装配（九阶段，顺序不可重排）────────────── §8
            │
   ⑧ 组装出片委托 + 选定画师 ─────────────────── §13
            │
   ⑨ 出片（端口另一侧，本文不规定其形态）
            │
   ⑩ 回执落库：字节 + 那份**实际交出去的画稿** ───── §15
            │
   ⑪ 更新连贯档 ──────────────────────────────── §12
            │
   ⑫ 画位切到新稿次，图淡入 ────────────────────── §16
            │
   （玩家验稿 → 改稿 → 回到 ⑦，跳过 ⑥）─────────── J3
```

### 5.2 逐步说明

**① 扫描取景标记.**
在叙事 Agent 产出的**原始文本**上扫描，不在渲染后的 HTML 上扫描。
每个标记按出现顺序编号；缺 `id` 属性的补一个短随机号**并写回正文**——
补齐只发生这一次，此后那个号就是不变量。正文入库时标记原样保留。

**② 暂存到流程末尾.**
扫到标记不立刻出片，先暂存。整条编排流程跑完、状态回读完成之后，才在 `run()` 末尾统一放行。

> 这一步值得单独解释：Stage 1 时刻的世界还是**上一幕**的——地点没更新、
> 新角色没落库、服装变更没写进状态。在那个时刻取连贯档（第 ⑤ 步）会取到过期数据，
> 画出来的是上一幕的场景。这个 bug 的形态是"图总是慢半拍"，
> 而且因为它每次都能出图，很容易被当成模型的问题。

**③ 画位建立与命中.**
按画位号查画位索引。若该画位已有当前稿（回退快照后走回原路、页面刷新、切走再切回），
**直接呈现既有稿次，不重新出片**。这是省钱也是省时间的一步。

**④ 入队.**
自动模式下受每轮配额约束，超额的画位落为待出片；手动模式下等玩家点击。
入队时做去重：同一画位已在飞则忽略本次。

**⑤ 取连贯档.**
按标记上的主体角色与场景取连贯档条目。取到的是**结构化字段**（外貌 / 服装 / 状态 / 场景 / 画风），
不是上一张图的词串。

**⑥ 译稿.**
标记体是自然语言句子时，交译稿 Agent 转成词串；已经是词串时跳过；
玩家手改过的画稿**永远跳过**。同一轮的多个标记合并为一次调用。
**失败即透传**：用原文继续，不阻断。

**⑦ 画稿装配.**
九个阶段，顺序不可重排（§8.1）。这一段是纯函数：同样的输入永远得到同样的画稿。
可测试性优先级最高的就是这一段。

**⑧ 组装出片委托.**
把画稿、参数、参照图、排位结构装进一份**出片委托**，按笔法或全局默认选定画师。
画师的能力位决定排位结构是原样带上还是先展平（§13.3）。

**⑨ 出片.**
端口另一侧的事。画室只知道三件事：成功了、失败了（带可读原因）、被取消了。

**⑩ 回执落库.**
字节进字节表，元数据进稿次表。元数据里**必须含那份实际交出去的画稿与实际生效的随机种**——
缺了它，验稿面板显示的和真正发出去的就是两个东西，而这种不一致极难自查（§13.2）。

**⑪ 更新连贯档.**
按译稿 Agent 返回的结构化字段更新服装/状态/场景；外貌只读不写；锁定项跳过。

**⑫ 呈现.**
画位由"出片中"切到"已就绪"，图淡入。占位块此前已按宽高比占住了最终高度，所以正文不跳动。

### 5.3 这条历程上的四个不变量

| 不变量                     | 违反后的表现                                 |
| -------------------------- | -------------------------------------------- |
| 画位号在正文里，且只写一次 | 画位与图的绑定会在改名/重排/改稿后丢失       |
| 出片一律发生在流程末尾     | 图总是慢半拍，画的是上一幕                   |
| 装配阶段是纯函数           | 同一份输入两次出图得到不同画稿，问题不可复现 |
| 回执里带着真实画稿与随机种 | "我想要刚才那张但改一个词"这件事做不到       |

## 6. 取景标记

### 6.1 语法

```xml
<draw_shot id="a3f1" subject="苏婉" scene="酒馆二楼" mode="manual">
夜色，木质包厢，苏婉靠在窗边侧头看向门口，半身，暖色灯光
</draw_shot>
```

- **标签名** `draw_shot`，纳入既有 Marker Protocol 标签集，与 `play_audio` 等同级。
- **标记体**：一段自然语言画面描述，或一串已成形的词串。两种形态都接受，
  区别只在于第 ⑥ 步是否触发译稿。
- **属性**（全部可选）：

| 属性      | 含义                                    | 缺省       |
| --------- | --------------------------------------- | ---------- |
| `id`      | 画位号（§7）                            | 扫描时补齐 |
| `subject` | 画面主体角色名，用于取连贯档与画词典    | 无         |
| `scene`   | 场景名，用于取场景连贯档                | 取当前地点 |
| `mode`    | `auto` / `manual`，覆盖全局自动出片开关 | 跟随全局   |

### 6.2 为什么是 XML 标记

- 与既有六类标记同构，扫描器、属性解析、嵌套约束全部复用，**不引入第二套协议**。
- **不与 Markdown 冲突**。任何以 `#`、`~`、`*`、`` ` `` 开头结尾的分隔符方案，
  都会在某些模型的输出里被 Markdown 吃掉（例如独占一行的三个井号会变成三级标题），
  于是你被迫再写一层"把被渲染坏的标记拼回来"的修补逻辑。
  选一个 Markdown 不可能解释的形状，那一整块修补逻辑就不必存在。
- **开闭标签不重叠**。任何"开标记以闭标记结尾"的设计在畸形输入下会捕获空串，
  且非贪婪匹配会让最近的闭标记胜出。成对 XML 标签天然没有这个问题。

### 6.3 扫描规则

- 扫描对象是**消息原始文本**。呈现层拿到的是已解析好的画位列表，
  它永远不需要去 HTML 里找标记。
  > 一旦扫描 HTML，注入的换行标签、强调标签、代码块包装都会混进描述里，
  > 你就得再写一层"从 HTML 里把描述洗出来"的归一化，而那层归一化必然有损。
- **不支持嵌套**，与既有标记约束一致。
- 每条消息标记数量有上限（默认 8）。**超出的部分原样呈现为普通文本并给出一次提示**，
  不静默丢弃——静默丢弃会让玩家以为模型没写标记。
- 截断保留**靠前的 N 个**（正文靠前的画面通常是场景建立镜头）。
  这条可配置，但缺省行为必须在文档与 UI 里写明，不能靠读代码才知道砍的是哪一头。

### 6.4 正文的存留分工

| 阶段            | 行为                                                     |
| --------------- | -------------------------------------------------------- |
| 入库            | 正文**原样保留**标记。它是画位的锚，剥掉就再也定位不回来 |
| 呈现            | 美化管线把每个标记替换为画位组件；标记本身不可见         |
| 导出 / 复制正文 | 剥离标记，只留纯文本                                     |
| 回退快照        | 正文回退即画位回退；稿次记录**不删除**（§15.4）          |

---

## 7. 画位与稿次

### 7.1 画位号

画位身份 = **写在正文里的显式画位号**，辅以 `(消息 ID, 标记序号)` 作为兜底定位。

消息 ID 是数据库主键，不是展示字段：它不随角色改名、时间戳重写、消息重排而改变。

### 7.2 为什么不用内容推算

一个很自然的诱惑是"拿描述内容加上消息元信息算个摘要当身份"。不要这么做：

- 画稿是**可改写的**（J3）。玩家改一个字，摘要就变，绑定的图当场丢失。
- 消息元信息里能拿到的多数字段是**展示数据**（显示名、时间戳、楼层号），全都会变。
- 一旦身份从可变字段派生，你就必须再写一条"主键没命中就依次试若干退化键、
  命中后迁移回主键"的自愈链。那条链能工作，但它存在的唯一原因是身份选错了。
- 显式号写在正文里，成本是多几个字符，收益是整条自愈链不必存在。

### 7.3 画位状态机

```
待出片 ──点击/自动──▶ 排队中 ──▶ 出片中 ──成功──▶ 已就绪
   ▲                                  │
   └──────────── 失败（可重试）◀───────┘
```

- **已就绪**画位可再次入队（重画），旧稿不删，进稿次列表。
- **出片中**的画位对同一画位的重复触发幂等：第二次点击不排第二个任务。
- 页面刷新后，"排队中/出片中"一律回落为"待出片"。
  **在飞任务不跨会话恢复**——恢复它需要服务侧支持任务查询，那是个能力位而非通用前提。

### 7.4 稿次

| 字段       | 说明                           |
| ---------- | ------------------------------ |
| 序号       | 初稿 / 次稿 / 三稿……           |
| 画稿       | 实际交出去的入画词与忌避词     |
| 参数       | 实际生效的尺寸、随机种、步数等 |
| 画师       | 服务名与模型名                 |
| 时间与耗时 |                                |
| 是否当前稿 | 每画位恰有一稿为真             |

稿次不自动清理。清理由"清除未引用稿次"这个显式维护操作完成（§15.4）。

## 8. 画稿装配

### 8.1 九阶段，顺序不可重排

| #   | 阶段             | 作用                                                   |
| --- | ---------------- | ------------------------------------------------------ |
| 1   | **内联指令摘出** | 摘出 `size:` `style:` `seed:` 等指令并从描述文本中删除 |
| 2   | **忌避段分离**   | 摘出内嵌的忌避段，并入忌避词一路                       |
| 3   | **译稿结果并入** | 若第 ⑥ 步跑过，用其结果替换描述文本                    |
| 4   | **连贯档展开**   | 把连贯档的结构化字段展开为词串并合并                   |
| 5   | **画词典替换**   | **全流程有且只有这一次**                               |
| 6   | **排位解析**     | 拆成场景段 + 每角色段（含角色忌避与站位）              |
| 7   | **笔法包夹**     | 前置笔法 + 正文 + 后置笔法                             |
| 8   | **清洗归一**     | 逗号折叠、空白折叠、首尾裁剪、全角修正                 |
| 9   | **委托成形**     | 装进出片委托；能力缺席时在此展平（§13.3）              |

装配是**纯函数**：同样的输入永远得到同样的画稿。它不读数据库、不读时钟、不掷随机数
（随机种由调度层在入队时定好并传入）。这条约束让整段可以被穷尽测试，
也让"为什么这次出来的图不一样"永远有确切答案。

### 8.2 画词典只跑一次

**硬约束。** 词条的输出可能再次匹配另一条词条（甚至匹配自己），跑两次不等于跑一次。
若某条词条恰好幂等，跑两次"看着没问题"——直到玩家写了一条不幂等的词条，
然后得到一个无法复现的 bug。

替换点固定在阶段 5：**在连贯档展开之后**（连贯档字段本身也该享受词典），
**在排位解析之前**（这样角色名展开出的描述才落进正确的角色段）。

### 8.3 忌避段分离

描述文本里若出现忌避段引导词（中英文冒号均认），其后内容整体移入忌避词一路，并从入画词移除。

边界要写明：这个匹配**贪婪到文本末尾**——引导词之后的所有内容都会变成忌避词。
这是刻意的（模型习惯把忌避段写在最后），但必须在 UI 提示里说清楚，
否则玩家会写出"忌避段之后又接一段入画词"然后困惑。

### 8.4 清洗规则

固定四步，顺序固定：

1. 连续逗号折叠为一个
2. 逗号两侧空白剥除（线格式统一为 `a,b,c`，逗号后不留空格）
3. 首尾逗号剥除
4. 连续空白折叠为单空格，首尾裁剪

外加**全角修正**：全角逗号归一为半角；全角书名号 `《》` 归一为尖括号 `<>`。
后者非常重要——中文输入法环境下模型极易把 `<外挂模型:名字:权重>` 写成书名号形态，
不修就直接失效，而且失效是静默的。

### 8.5 尺寸与随机种

尺寸来源，从高到低：

1. 本次委托的显式覆盖（重画时玩家在验稿面板改的）
2. 内联 `size:` 指令
3. 生效笔法的默认尺寸
4. 画师的默认尺寸
5. 系统兜底值

`size:` 每轴取值范围 64–8192。**越界值视为无效指令并提示**，不静默忽略。

随机种：`-1` / 空 / `0` 一律表示"随机"。随机结果**必须在入队时定下并写进稿次**，
不能留给画师去随。否则"我想要刚才那张但改一个词"这件事做不到。

## 9. 笔法

### 9.1 形态

一个笔法包含：

| 字段                              | 说明                                     |
| --------------------------------- | ---------------------------------------- |
| 名称                              | 唯一，按名寻址（对齐"AI 永不产 id"铁律） |
| 前置入画 / 前置忌避               | 拼在正文**之前**                         |
| 后置入画 / 后置忌避               | 拼在正文**之后**                         |
| 默认尺寸 / 步数 / 强度 / 采样方式 | 参数默认值，被更高优先级来源覆盖         |
| 绑定画师                          | 可选。切笔法即切画师                     |

**前后双侧包夹**是必要的：画质类词习惯放前面，镜头与风格类词习惯放后面，
只给一侧会逼玩家把两类东西塞进同一个格子。

### 9.2 三条细则

- **跳过笔法**：某些委托（玩家给了完整画稿、重画一份已完整的稿次）需要绕过两侧包夹。
  这是一个显式的委托级开关，不是靠"把笔法设空"实现。
- **单次覆盖**：内联 `style:名称` 让**这一张**临时换笔法，不改变全局生效笔法。
- **后置去重**：拼接后置忌避前先看该路是否已含该片段，已含则跳过。
  否则玩家会在同一条忌避词里看见三遍同一个词。

### 9.3 笔法 ≠ 画师配置

前者是"画成什么样"，后者是"交给谁画"。UI 上必须是两个分区。
笔法可以（可选地）绑定画师，反向不成立。

## 10. 排位语法

### 10.1 写法

```
场景:  两名少女，酒馆二楼包厢，夜
角色1: 苏婉, 蓝色长发, 侧头微笑 |站位:c3
角色1忌避: 多手
角色2: 亚瑟, 银发, 靠墙抱臂 |站位:a2
忌避: lowres, bad anatomy
size: 832x1216
style: 水彩
```

- 每条以换行或分号终止。段头名称可配置，支持中英文别名。
- **舞台格**为 5×5：列 `a`–`e`、行 `1`–`5`，各映射到画面归一化坐标 0.1 / 0.3 / 0.5 / 0.7 / 0.9。
- `站位:auto` 表示"交给模型自己排"。
  **任意一个角色写了 `auto`，整张图的站位机制就整体关闭**——
  一半角色钉死站位、一半自由摆放，产生的构图比全自由更糟。
- `size:` 与 `style:` 被消费后**从文本中删除**；无效的 `size:` 保留在文本里并提示（§8.5）。

### 10.2 展平

画师不具备区域控制能力位时，排位结构在装配第 9 阶段**展平**：
场景段与各角色入画段按序合并为一路入画词。

**展平必须保留角色忌避**：把所有角色的独立忌避**并入全局忌避词**，而不是丢弃。
丢弃是最省事、也最容易让玩家以为"排位语法在这个画师下没用"的做法；
实际上忌避词在展平后依然有效，只是不再是逐角色的。

### 10.3 区域推导

具备区域控制能力位时，由站位推出区域：
以坐标点为中心横向展开 ±0.25、纵向展开 ±0.40，裁剪到 `[0,1]`，保留两位小数；
多角色时权重递减（首个角色最高）。

推导本身是纯几何，属装配层；**如何把区域表达给画师是端口另一侧的事**。

## 11. 译稿 Agent

### 11.1 职责

把叙事化的自然语言（"夜色，木质包厢，苏婉靠在窗边侧头看向门口"）
译成成像模型吃得下的词串。

复用既有 Agent 基建：ApiEndpoint（含鉴权与超时）、AgentConfig（模型/温度/上限）、
模板系统（可编辑的多轮消息数组 + 占位符）、重试与退避。**不新建一套客户端。**

### 11.2 何时触发

| 标记体形态                                                          | 行为                             |
| ------------------------------------------------------------------- | -------------------------------- |
| 自然语言句子                                                        | 走译稿                           |
| 已成词串（启发式：逗号密度高、无句末标点、多为小写 ASCII 或已知词） | 跳过                             |
| 玩家在验稿面板手改过                                                | **永远跳过**——玩家改的就是最终值 |

判定不确定时**倾向于走译稿**：多花一次调用，好过把一句中文句子直接扔给成像模型。
但必须有一个全局开关能强制关闭译稿。

### 11.3 可携上下文（各项独立开关）

| 上下文       | 来源                                    |
| ------------ | --------------------------------------- |
| 角色外观资料 | 角色状态的外貌字段 + 世界书中该角色条目 |
| 剧情上下文   | 标记所在消息的前后若干段正文            |
| 连贯档       | §12                                     |
| 词库参考     | 玩家导入的词表（含屏蔽词）              |
| 目标风格说明 | 玩家自定的"我想要什么样的词"            |

### 11.4 输出契约：结构化，不是从散文里捞

**译稿 Agent 必须返回结构化结果**（JSON 模式或工具调用），至少含：
入画词、忌避词、以及可选的连贯档更新。

不要用"让模型把答案写进某个标记里，再从散文中抠出来"的方案。那条路会逼你写一整套救援启发式——
"取最后一次出现的某关键词之后的内容""若首字符是字母或括号则整段视为答案""
剥掉开头的思维链标签再拼回去"——每一条都是对某个具体模型某种具体啰嗦方式的补丁，
且它们互相之间会打架。有结构化输出可用时，这整摞启发式都不必存在。

模型仍可能在结构化字段之外写思维链——**忽略即可，不解析**。

### 11.5 失败即透传

译稿失败（超时、鉴权错、不合契约、被安全策略拒绝）时，
**原样使用未译的文本继续出片**，并在画位上标一个"未经译稿"的小标识。
不弹错、不阻断、最多重试一次。

### 11.6 批量合并

同一轮正文中的多个标记合并为**一次**译稿调用（请求里带多个条目，响应按序返回）。
这是显著的成本优化，且合并后模型能看到整轮的全部画面，连贯性反而更好。
合并上限可配置，超限拆批。

## 12. 连贯档

### 12.1 问题

连续配图里，同一个角色的发色、瞳色、服装、发型不该无理由跳变。

### 12.2 方案：结构化档案，而不是"把上次的词串贴过来"

每存档维护一份连贯档，按角色分条，字段固定：

| 维度 | 例                               | 写入方                        |
| ---- | -------------------------------- | ----------------------------- |
| 外貌 | 发色、瞳色、发型、体型、种族特征 | 角色数据 + 世界书（画室只读） |
| 服装 | 上装、下装、鞋、配饰             | 每次出片后更新                |
| 状态 | 表情、姿态、伤势、临时状态       | 每次出片后更新                |
| 场景 | 地点、时间、天气、光照           | 每次出片后更新                |
| 画风 | 生效笔法                         | 跟随笔法                      |

译稿 Agent 在结构化输出里返回一个**显式的延续标志**：本张是延续上一幕（沿用档案）
还是场景切换（重置临时维度、保留外貌）。这个判断交给模型，因为它是叙事判断；
但**结果落在结构化字段上**，由 Code 决定怎么用。

### 12.3 为什么不是"贴词串"

把上一张图的词串原样塞进这次的画稿里，有三个问题：

1. 词串**单调累积**——每轮都比上轮长，最后画稿里塞满几十轮前的残留。
2. 无法表达"这一项该换了"。角色换了衣服，旧词还在，模型收到互相矛盾的两组服装描述。
3. 无法被玩家检查与修正。结构化档案可以在 UI 上列出、逐项编辑、**逐项锁定**。

逐项锁定是额外红利：玩家可以钉死"她的发色永远是这个"，而让其他维度自由变化。

### 12.4 生命周期

- 随存档隔离，进快照。回退快照时连贯档一并回退。
- 场景切换（地点变化 / 显式重置）清空临时维度，保留外貌与锁定项。
- 设置里可一键重置全部连贯档。

## 13. 成像端口

> **本章刻意抽象。** 具体接哪家服务、走什么协议、参数怎么映射、响应怎么解，
> **不在本设计文档的范围内**——那一层预期会变。
> 本章只规定端口两侧的契约、能力模型，以及能力缺席时的降级行为。
> 只要一个新服务能填满 §13.1 与 §13.2 的两份契约并声明自己的能力位，
> 它就能接进来，且画室的其余部分**一行都不必改**。

### 13.1 出片委托（画室 → 画师）

| 项              | 说明                                                                |
| --------------- | ------------------------------------------------------------------- |
| 入画词 / 忌避词 | 已完成全部装配变换的最终两路词串                                    |
| 排位结构        | 场景段 + 角色段数组（每段含入画、忌避、站位）；已展平或无排位时为空 |
| 画幅            | 宽、高                                                              |
| 出片参数        | 步数、引导强度、采样方式、随机种（**已定值，不是 -1**）             |
| 参照图          | 可选。源图字节 + 参照强度                                           |
| 遮罩            | 可选。仅在具备局部重绘能力位时有意义                                |
| 跳过笔法        | 布尔                                                                |
| 取消信号        | 允许调度层中止                                                      |

**这份契约必须在接第一个画师之前定下来。** 反过来做——先接一个服务再抽象——
的结果是把第一个服务的形状漏进所有服务。
具体地说：不要把一个"带着若干松散字段的临时对象"在层间传来传去，
更不要把界面元素本身当参数传递；那样契约就无从谈起，
而且每个新接入的服务都会顺手往那个对象上再挂两个字段。

### 13.2 成片回执（画师 → 画室）

| 项                              | 说明                                              |
| ------------------------------- | ------------------------------------------------- |
| 成败                            |                                                   |
| 图像字节                        | 统一为二进制（不是 data URL，不是 base64 字符串） |
| 媒体类型                        | 为将来的动图/影像留口                             |
| **实际交出去的入画词 / 忌避词** | 见下                                              |
| 实际生效参数                    | 尺寸、随机种、步数等                              |
| 画师信息                        | 服务名、模型名、耗时                              |
| 失败原因                        | 可读文本 + 一句可操作建议                         |

**"实际交出去的画稿"是不可省的一条缝。** 验稿面板、重画、问题排查全依赖它。
缺了它，玩家看到的和真正发出去的就是两个东西，而这类不一致极难自查——
它不会报错，只会让每一次"我明明改了却没变化"的困惑都无从下手。

### 13.3 能力位与降级矩阵

画师向端口声明自己支持哪些可选能力。画室**只按能力位分叉，不按服务名分叉**。

| 能力位                               | 缺席时的降级                                                     |
| ------------------------------------ | ---------------------------------------------------------------- |
| **区域控制**（逐角色区域与独立忌避） | 排位结构展平；角色忌避并入全局忌避（§10.2）                      |
| **逐角色忌避**                       | 角色忌避并入全局忌避，其余排位信息保留                           |
| **站位坐标**                         | 丢弃坐标，保留角色分段                                           |
| **参照图**                           | 参照图被忽略，**并在画位上明确标注"该画师不支持参照图"**，不静默 |
| **局部重绘**                         | 遮罩被忽略并明确标注                                             |
| **模板填格**（玩家提供请求模板）     | 走该画师的固定参数映射                                           |
| **任务轮询**（返回任务号而非成片）   | 无——不具备时按同步返回处理                                       |
| **外挂模型语法**（内联的模型引用）   | 内联引用**从词串中剥除**而不是原样发送                           |

降级必须满足两条：

1. **能降的一律降，不报错。** 玩家不该因为换了画师就看到一堆红字。
2. **降级必须可见。** 在画位或验稿面板上标注"本次因画师能力所限，已展平排位/忽略参照图"。
   静默降级会让玩家反复调整一个根本没生效的设置。

### 13.4 填格约定（具备模板填格能力位时）

玩家提供请求模板，画室按具名填格注入实际值。

- **填格必须带界定符**，形如 `{{入画词}}`、`{{宽度}}`、`{{随机种}}`。
  裸词填格（直接拿"宽度"两个字当哨兵）会与真实描述内容冲突——
  玩家写了一段含"宽度"二字的描述，那两个字就会被替换掉。
- **填格解析为空时报错，绝不静默发送。** 静默发送的后果是画师收到字面量填格，
  产出一张与描述毫无关系的图，而玩家完全不知道发生了什么。
- 替换顺序：先替换所有非词串填格，再替换词串填格。
  （即使有界定符也保留这个顺序——描述里出现 `{{宽度}}` 字样虽罕见但不是不可能。）
- **模板导入时即校验填格齐全并列出缺失项**，而不是等到出片失败。

### 13.5 画师配置

- 画师配置是**具名档案**（名称 + 连接信息 + 模型 + 默认参数 + 能力位），可存多份、可切换。
- 全局默认画师一个；笔法可绑定画师；委托可显式覆盖。三级优先级由低到高。
- 提供"连接测试"，测试内容包括**能力位探测**，探测结果缓存并可手动刷新。

### 13.6 端口两侧的共性约束

- 所有画师共享同一套超时、重试、取消语义，由调度层统一持有，不由各画师自行实现。
- 所有画师失败时返回**同一种错误形状**，调度层与呈现层不做画师判别。
- 画师不得访问画位、正文、连贯档或任何存档数据。它只看见一份出片委托。

## 14. 画室调度

### 14.1 默认串行

成像服务多为单任务串行，并发请求只会让每个都变慢或直接排队超时。

- 默认**同时只有一个任务在飞**，其余进 FIFO 队列，画位上显示队列位次。
- 提供"允许并发"开关（默认关）+ 并发上限（默认 2）。

### 14.2 冷却

两次委托之间插入可配置的最小间隔（默认 500ms–1s，按画师档案配置）。这是对限流的粗粒度保护。

> 设计提示（非实现指引）：冷却应由一个显式的调度器持有。
> 不要用一个布尔标志同时表达"有没有在出片"和"该不该等一下"——
> 一个字段承担两个含义是这类系统里最常见的状态腐坏来源，而且这种字段的名字通常还是反的。

### 14.3 去重

维护在飞画位集合，保证一个画位同时只有一个任务。
入队时查、出队时查、完成后**无论成败**都移除。

### 14.4 自动出片配额

| 配额              | 默认                 | 说明                     |
| ----------------- | -------------------- | ------------------------ |
| 每轮自动出片上限  | 3                    | 超出的画位留作手动       |
| 已有当前稿的画位  | 跳过                 | 除非玩家显式重画         |
| 切存档 / 切角色后 | 抑制一轮             | 避免切换瞬间批量触发     |
| 回退快照后        | 抑制                 | 回退不该触发出片         |
| 鉴权类失败后      | 暂停本轮剩余自动出片 | 凭据错时批量重试毫无意义 |

这些配额不是性能优化，是**成本保护**。按张计费的服务上，
一次失控的批量自动出片可以在玩家没注意时烧掉可观额度。

### 14.5 取消

排队中可取消（直接出队）；出片中可取消（向端口发取消信号，能否真正中止取决于画师）。
取消后画位回到"待出片"，不产生失败稿次。

## 15. 存储模型

### 15.1 两张表

| 表         | 内容                                                                                      | 隔离   |
| ---------- | ----------------------------------------------------------------------------------------- | ------ |
| 稿次元数据 | 稿次 ID、画位号、存档 ID、消息 ID、序号、实际画稿、参数、画师、时间、字节引用、是否当前稿 | 随存档 |
| 稿次字节   | 图像字节                                                                                  | 随存档 |

**元数据与字节分表**，理由与既有音频/素材子系统一致：
列表页、验稿面板、导出清单全都只需要元数据；
放一张表意味着任何一次列表查询都在搬几十 MB 字节。

### 15.2 ID 策略

**用 UUID，不用自增整数。**

自增整数需要"开游标读最大值再加一"，多标签页并发时会撞号，
后果是一条稿次覆盖另一条——一个几乎不可能在测试里复现、只在真实使用里偶发的数据丢失。

### 15.3 画位索引

一张 `画位号 → 当前稿 ID` 的索引，随存档加载进内存。
呈现层只查这张索引，不直接查表。在飞画位在索引里挂一个标记，供去重使用（§14.3）。

### 15.4 与快照/回退的关系

- 快照记录**画位索引**，不记录字节。
- 回退快照 → 画位索引回退 → "未来"的图消失，"过去"的图回来。
- **稿次记录永不随回退删除。** 玩家可能回退后又走回同一条路，此时旧图应当直接命中（§5.2 第 ③ 步）。
- 孤儿稿次由"清除未引用稿次"这个显式维护操作回收，**不做自动 GC**。

### 15.5 与素材库的关系

成片**不进素材库**。两者性质不同：

|          | 素材库        | 画室               |
| -------- | ------------- | ------------------ |
| 键       | 角色名 + 类型 | 画位号             |
| 隔离     | 全局共享      | 随存档             |
| 数量级   | 几十张        | 数百张             |
| 生命周期 | 玩家长期维护  | 随剧情产生，可清理 |

但提供一条**单向出口**：验稿面板上的"存为立绘 / 存为头像"，
把这张图交给既有裁剪台，由裁剪台产出真字节落进素材库。
名字由打开方给定（取标记的 `subject`），**裁剪台不提供名字输入框**——
这与素材系统既有约定一致：命名入口只有一个。

### 15.6 导出

- "导出本存档配图"为压缩包：图片文件 + 一份清单（画稿、参数、画位、时间）。
- **不进 FullBackup。** 这一点必须写进存档管理页的文案。

## 16. 呈现与交互

### 16.1 画位组件的四态

| 状态            | 呈现                                                           |
| --------------- | -------------------------------------------------------------- |
| 待出片          | 低调的行内按钮：图标 + 描述首若干字的省略预览                  |
| 排队中 / 出片中 | 同尺寸占位块 + 进度指示 + 取消按钮。**占位块必须占住最终高度** |
| 已就绪          | 图。宽度受"配图缩放"设置约束，默认不超过正文栏宽               |
| 失败            | 占位块 + 简短原因 + 重试按钮                                   |

**占位块占住高度**是为了防止"图加载完成时正文整体跳动"——
正文跳动会把玩家正在读的那一行弹走，是沉浸感的直接杀手。
高度由委托里的宽高比推算，在图出来之前就已知。

### 16.2 懒加载

- 用可视区观察器注册占位图，进入视口前后约一屏的缓冲区时开始加载。
- **另配一条兜底**：注册后短延时再做一次几何检查。
  某些低端设备/浏览器组合下观察器回调不触发，只有观察器时表现为"图永远不出来"。
  两条机制并存是刻意的冗余。
- 字节 → 显示地址的转换必须**引用计数**：
  同一张图可能同时出现在正文与看图台里，无计数的释放会让先卸载的一方把地址从另一方手里撤掉，
  表现为"打开看图台后正文里的图变白"。
- 释放顺序：**先铸新的再撤旧的**。反过来会闪一帧空白。

### 16.3 交互

| 操作        | 结果                                                          |
| ----------- | ------------------------------------------------------------- |
| 单击图      | 打开看图台（全屏、缩放、上/下一张）                           |
| 右键 / 长按 | 菜单：重画 / 改稿 / 稿次列表 / 存为素材 / 复制画稿 / 删除     |
| 验稿面板    | 见 J3。展示实际画稿、全部参数、画师、耗时、随机种；画稿可改写 |

### 16.4 遮罩

可选全局开关：所有配图默认盖一层模糊遮罩，点击才显形。
适用于"和别人共处一室时也想玩"的场景。遮罩状态**不持久化**，每次进入页面重置为遮住。

### 16.5 减少动效

所有淡入/缩放动效必须尊重 `prefers-reduced-motion`，退化为瞬间切换。

## 17. 设置界面

设置页新增「配图」分区，四段式：

### 17.1 行为

启用画室（总开关）· 自动出片 + 每轮上限 · 配图缩放 · 遮罩 · 允许并发 + 并发上限 + 冷却间隔

### 17.2 画师

- 画师档案列表（增删改、设为默认、连接测试与能力位探测）
- 每档案：连接信息、模型、默认参数
- 具备模板填格能力位者：模板导入/管理 + **导入时的填格齐全性校验**
- 探测到的可选资源（模型列表、采样方式等）缓存展示并可手动刷新
- **此分区的具体字段随画师形态而定，不由本文档规定**

### 17.3 笔法与词库

笔法（增删改、生效前后置）· 外挂模型预设 · 画词典词条（查找 → 替换，支持正则，
非法正则只跳过该条并提示，不让整表失效）· 默认忌避词

### 17.4 译稿与连贯

启用译稿 · 选 ApiEndpoint 与模型（复用既有端点管理，不重复配置鉴权）·
上下文开关 · 提示模板编辑器 · 批量合并上限 ·
启用连贯档 + 逐维度锁定 + 当前档案查看/编辑/重置

## 18. 失败与降级

**总原则：画室的任何失败都不得影响叙事主流程。**

| 失败             | 降级行为                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| 未配置任何画师   | 画位呈现"未配置"提示，点击跳设置页                                       |
| 画师不可达       | 画位标失败 + 可读原因 + 重试；**不自动接着跑队列里的下一个**（避免雪崩） |
| 鉴权失败         | 同上，且暂停本轮剩余自动出片（§14.4）                                    |
| 译稿失败         | 失败即透传，用原文出片（§11.5）                                          |
| 能力位缺席       | 按矩阵降级并**明确标注**（§13.3）                                        |
| 填格解析为空     | **报错，不发送**（§13.4）                                                |
| 回执不是图像     | 报错，并把响应前若干字符呈现给玩家（通常是一段可直接读懂的错误信息）     |
| 存储配额耗尽     | 提示 + 给出"清除未引用稿次"入口；本次成片仍可临时查看但标"未保存"        |
| 标记数量超限     | 保留靠前的 N 个并提示（§6.3）                                            |
| 排位语法解析失败 | 整段按普通描述处理并提示，不中止出片                                     |

## 19. 内容安全

1. **系统提示是中性的任务说明。** 译稿 Agent 的默认提示只描述任务本身——
   把一段叙事文字译成绘图词串——不含任何人格覆盖、权限声明、安全策略否定，
   或"过滤已关闭"式的框架。这类框架对词串提取的质量没有帮助，
   反而占用上下文并降低指令遵循度。

2. **不内置任何内容类别授权清单。** 默认提示不枚举模型"被允许"生成的内容类别。
   玩家想生成什么，由玩家与其所选服务的条款决定，不由本系统的默认值预先声明。

3. **涉及未成年人的性化内容一律禁止**，无论玩家如何配置。这不是可配置项。
   过滤发生在译稿提示层与出片提交前的检查层，两处都做。

4. **默认提示随产品分发，因此必须可被逐字审阅。** 存放在配置文件而非硬编码，
   设置页可完整查看与编辑。

5. **第三方服务条款是玩家的责任，但系统要帮他知情**：
   配置画师档案时，在鉴权字段旁给出一句"该服务的内容政策由服务方决定"的提示。

## 20. 反模式清单

以下做法在这类系统里反复出现、代价高昂。每条都附了它会如何显形。

| #   | 反模式                               | 显形方式                                                       |
| --- | ------------------------------------ | -------------------------------------------------------------- |
| 1   | 从渲染后的 HTML 里扫描标记           | 描述里混进换行/强调标签，被迫写有损的归一化层                  |
| 2   | 身份从可变展示字段推算               | 改名/重排后全部图丢失，被迫写多级退化键自愈链                  |
| 3   | 开闭分隔符重叠                       | 畸形输入捕获空串；非贪婪匹配让最近的闭标记胜出                 |
| 4   | 分隔符与 Markdown 冲突               | 独占一行的分隔符被渲染成标题，标记永不匹配                     |
| 5   | 画词典跑多次                         | 非幂等词条产生无法复现的结果                                   |
| 6   | 装配阶段读时钟/掷随机                | 同一输入两次出图不同，问题不可复现                             |
| 7   | 裸词填格（无界定符）                 | 描述里恰好含该词 → 被替换掉                                    |
| 8   | 填格为空时静默发送                   | 画师收到字面量填格，产出无关的图，玩家无从察觉                 |
| 9   | 参数串用（借用另一功能的同名参数）   | 调一个功能的参数改变了另一个功能的行为                         |
| 10  | 互斥能力做成两个独立开关             | 后开的静默覆盖先开的                                           |
| 11  | 自增整数 ID（游标取最大值 +1）       | 多标签页并发撞号 → 记录互相覆盖                                |
| 12  | 回执缺"实际交出去的画稿"             | 面板显示的与实际发出的不一致，问题无法自查                     |
| 13  | 一个布尔同时表达"在出片吗"和"该等吗" | 状态腐坏，且名字通常还是反的                                   |
| 14  | 按画师名分叉而非按能力位分叉         | 每接一个新服务就要改一遍装配层                                 |
| 15  | 把松散临时对象/界面元素当跨层参数    | 契约无从谈起；每个新服务都往它上面再挂两个字段                 |
| 16  | 事件总线吞掉监听器异常               | 处理器里的错误彻底消失，排查从"看日志"变成"猜"                 |
| 17  | 同一功能两份实现                     | 畸形输入下行为不同；后定义的静默胜出                           |
| 18  | 展平时丢弃逐角色忌避                 | 玩家以为排位语法在该画师下"没用"                               |
| 19  | 从散文里用启发式抠模型答案           | 一摞互相打架的补丁；换个模型就得再加一条                       |
| 20  | 把上一轮词串原样贴进这一轮           | 单调累积；无法表达"这项该换了"                                 |
| 21  | 数量截断不说明砍的是哪一头           | 玩家以为模型没写；"算了后 N 个却渲染了前 N 个"这类错位极难发现 |
| 22  | 元数据与字节同表                     | 每次列表查询都在搬几十 MB                                      |
| 23  | 显示地址无引用计数                   | 一处卸载把地址从另一处手里撤掉，图变白                         |
| 24  | 在流程早期取连贯档/地点              | 取到上一幕的世界，画出上一幕的场景                             |
| 25  | 静默降级                             | 玩家反复调整一个根本没生效的设置                               |

## 21. 分期实施

每一期结束时系统都应当可用。

| 期                | 内容                                                                              | 完成即可                 |
| ----------------- | --------------------------------------------------------------------------------- | ------------------------ |
| **P1 主干**       | 取景标记 + 画位号 + 两张表 + 四态呈现 + 端口契约 + **一个最简画师**               | 手动点按钮出图并正确落位 |
| **P2 装配**       | 九阶段装配 / 内联指令 / 忌避分离 / 清洗 / 画词典（一次）/ 笔法前后夹 / 尺寸优先级 | 画稿行为完全确定且可解释 |
| **P3 调度与验稿** | 串行队列 / 冷却 / 去重 / 自动出片 + 配额 / 看图台 / 验稿面板 / 改稿 / 稿次列表    | J1 与 J3 打通            |
| **P4 译稿**       | 复用既有 Agent 基建 / 结构化输出 / 批量合并 / 失败即透传 / 模板编辑器             | 自然语言标记可用         |
| **P5 连贯**       | 连贯档 / 逐项锁定 / 延续标志 / 进快照                                             | 连续配图不跳变           |
| **P6 能力矩阵**   | 能力位声明 / 降级矩阵 / 降级可见 / 第二、第三个画师                               | 换画师不改装配层         |
| **P7 收尾**       | 排位语法 / 外挂模型预设 / 遮罩 / 导出包 / 存为素材 / 清除未引用稿次               | 功能完备                 |

**P1 的"最简画师"应当选一个失败原因一定在自己代码里的形态**——
没有跨域、没有打包响应、没有中继协议怪癖。它的作用是把主干跑通，不是把接入做全。

## 22. 验收标准

### 22.1 流程

- [ ] 叙事 AI 产出的取景标记就地呈现为画位，位置与所描述的段落对应
- [ ] 手动与自动两条路径都能出片
- [ ] 重画任意次，画位绑定不错位
- [ ] 刷新、切存档、回退快照后画位绑定仍正确；走回原路直接命中既有稿次不重出
- [ ] 画稿可改写，改写后在后续重画中保留，可还原
- [ ] 验稿面板展示的画稿与实际交出去的字节级一致
- [ ] 出片一律发生在流程末尾：连贯档取到的是本幕而非上一幕的世界
- [ ] 装配是纯函数：同一输入两次装配得到完全相同的画稿

### 22.2 能力与降级

- [ ] 至少两个能力位不同的画师，同一套排位语法在两者下都出片
- [ ] 每一种降级都在画位或验稿面板上可见
- [ ] 填格缺失在**模板导入时**被指出，而不是等到出片失败

### 22.3 健壮性

- [ ] 无画师 / 画师离线 / 鉴权错 / 回执非图像 / 配额满，五种情况各有明确可读的提示与出路
- [ ] 译稿失败时正文与出片均不中断
- [ ] 非法正则词条只跳过该条
- [ ] 一次自动出片不超配额；切档/回退不触发自动出片

### 22.4 体验

- [ ] 图加载不引起正文跳动
- [ ] 长对话（100+ 消息、50+ 配图）滚动流畅，非可视区图不占内存
- [ ] `prefers-reduced-motion` 下无动效
- [ ] 画位键盘可达（Tab 聚焦，Enter 出片/打开）

### 22.5 工程

- [ ] 每个新模块配套单元测试；纯函数模块（装配九阶段、排位解析、填格替换、降级矩阵）覆盖率优先
- [ ] 画师全部经注入缝测试，不依赖真实网络
- [ ] 两份端口契约有往返测试

## 24. 附录：语法速查

### 24.1 取景标记

```xml
<draw_shot id="a3f1" subject="苏婉" scene="酒馆二楼" mode="manual">
画面描述或词串
</draw_shot>
```

### 24.2 内联指令（写在标记体内，被消费后从描述中删除）

| 指令     | 例              | 说明                                       |
| -------- | --------------- | ------------------------------------------ |
| `size:`  | `size:832x1216` | 每轴 64–8192，越界视为无效并提示           |
| `style:` | `style:水彩`    | 仅本次生效，不改全局笔法                   |
| `seed:`  | `seed:12345`    | `-1` / 空 / `0` = 随机；随机结果入队时定值 |
| `忌避:`  | `忌避: lowres`  | 其后全部内容并入忌避词                     |

### 24.3 排位语法

| 段       | 例                                |
| -------- | --------------------------------- |
| 场景     | `场景: 两名少女，酒馆二楼，夜`    |
| 角色入画 | `角色1: 苏婉, 蓝色长发 \|站位:c3` |
| 角色忌避 | `角色1忌避: 多手`                 |
| 全局忌避 | `忌避: lowres`                    |

舞台格：列 `a`–`e` × 行 `1`–`5`，各映射 0.1 / 0.3 / 0.5 / 0.7 / 0.9。
`站位:auto` 交由模型排布，且一处 auto 即全图关闭站位。

### 24.4 标准填格（具备模板填格能力位的画师）

`{{入画词}}` `{{忌避词}}` `{{宽度}}` `{{高度}}` `{{画幅}}` `{{步数}}` `{{引导强度}}`
`{{随机种}}` `{{采样方式}}` `{{模型}}` `{{参照图}}` `{{参照图完整}}` `{{遮罩}}`
`{{遮罩完整}}` `{{外挂1}}`…`{{外挂4}}` `{{角色分段}}`

玩家可在画师档案里追加自定填格。所有填格解析为空时**报错而非静默发送**。

### 24.5 外挂模型内联语法

`<外挂:名字:权重>`。全角书名号自动归一为半角尖括号（中文输入法下的高频形态）。
不具备该能力位的画师上，内联引用**从词串中剥除**而不是原样发送。
