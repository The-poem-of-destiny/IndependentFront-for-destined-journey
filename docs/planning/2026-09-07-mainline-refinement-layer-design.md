# 主线细化层设计（剧情颗粒度弥补）

> **状态：设计定稿，未实施（2026-09-07）**
>
> **适用范围**：剧情系统的结构性空白期——大纲事件窗口未到达时的日常轮次。改剧情 Agent
> 提示词、`worldFlags.plotThreads` 事件线、事件线面板前先读本文。
>
> **一句话定位**：主线是宏观大方向，细化层把它实例化为带动机的 NPC 行动，行动之间用伏笔
> 连线；职责上与既有大纲事件树（`plotEvents`）和无关随机事件（ADR-32）三足分立。

## 0. 一句话架构

在剧情事件窗口之间的空白期，`plot_pre_check` 按 Code 节奏闸门现编「主线细化节点」：把宏观
主线方向落地为「某 NPC 因为什么动机做了什么」，节点带伏笔引用（`foreshadows`/`payoffs`）自动
连成事件线；`plot_post_check` 在正文落定后结算节点状态。事件线住 `worldFlags.plotThreads`
（照 ADR-32/33 事实态先例，零新 Dexie 表、随存档进出），用户经事件线面板查看，AI 经 pre_check
上下文快照感知。无关氛围事件维持 ADR-32 现状不动。

## 1. 问题：大纲颗粒度与游玩颗粒度

### 1.1 现状证据

- 大纲事件带 `timeWindow`（年-月粒度，如 `488-04 ~ 488-06`），是剧情系统的最小单位。
- 实际游玩以天为颗粒度。真机样例：24 个回合约过 3 天，而最近的主线事件窗口在数月之后。
- `plot_pre_check` 模板被规则第 6 条约束——「没有任何事件满足条件是常态，不要为了有产出而
  硬触发」。窗口未到期间它的 `triggeredEvents` 恒为空，正文靠 Story 自由发挥日常，形成
  结构性空白期。

### 1.2 结论

不是「跨度大」的问题，是**颗粒度差**的问题：大纲最小单位是月，游玩单位是天，中间隔着约
一个数量级。空白期内主线零推进、日常平淡。需要一个把月粒度主线「细化」到日粒度的层。

## 2. 职责分层

| 层               | 内容                                                            | 归属                                           |
| ---------------- | --------------------------------------------------------------- | ---------------------------------------------- |
| 主线细化层（新） | 把宏观主线方向实例化为 NPC/势力的微观行动（带动机、带伏笔回收） | `plot_pre_check` 现编 + `plot_post_check` 结算 |
| 主线事件本身     | 窗口到达、条件满足时触发                                        | 现有管线（不变）                               |
| 无关氛围事件     | 抢劫、偶遇、小插曲，与主线无关                                  | ADR-32 事件系统（不变）                        |

三足分立：细化层是主线的**投影**，事件树是主线的**骨架**，随机事件是主线的**题外话**。

## 3. 主线细化小事件（目标态定义）

### 3.1 是什么

**它是主线的落地，不是主线的征兆。** 主线是一个大世界大方向（宏观向量），小事件是这个
方向在世界里的具体投影：

> 主线大方向：地城封印瓦解、势力在博弈。
> 细化出来的：冒险者公会因近期赏金流失向树海发布更多委托；炼金公会因雾蕈原料短缺开始抬价
> 收购，而高价收购人其实是某个势力的眼线；城门口传道的僧侣反复念叨「地下的低语」。

### 3.2 四项特征

1. **有主体、有动机、有行为**——每个小事件都落在具体的人和事上：某 NPC 基于某个利益或
   信仰，做了什么。世界在主线方向上真实运转。
2. **伏笔与回收**——小事件之间是一条编下去的链：本轮埋下的细节（某人收购雾蕈、传道人那句
   「低语」）在数轮后兑现或回收，成为后续事件的因果一环。玩家能感到「之前见过的东西又出现
   了，这次明白了它意味着什么」。
3. **不剧透主线终局**——NPC 们不知道大方向全貌，各做各的事。玩家看到一地碎片的真实世界，
   而不是「最后通牒」式预告。小事件不点名大纲事件标题、不预告窗口。
4. **与当前场景自然融合**——不打断玩家正在进行的动作（约会中出现的是一阵拂过窗棂的潮风，
   而不是拦路抢劫）。

### 3.3 不是任务

小事件是「迹象与运转」，不是「迷你任务」。玩家可参与可无视，参与与否不阻塞主线程到达，
也不会退化成拖着玩家的待办清单。

## 4. 事件节点与伏笔连线（存储形状）

### 4.1 节点

主线细化小事件作为**节点**存储：

```
name          节点名 —— AI 产，铁律①按名寻址，pre/post 都用名字引用
gist          一句话简述：这个节点是什么
thread        所属主线锚：挂到哪个大纲事件/大方向标题下
motive        动机：谁、因为什么、做了这件事
involvedNpcs  涉及 NPC 名单
status        dormant 沉睡 / active 活跃 / resolved 已回收 / dissolved 消散
foreshadows   它埋向哪些节点（伏笔引用，可选）
payoffs       它回收了哪些节点的伏笔（可选）
seededAt      埋设时间（游戏时间戳）
resolvedAt    回收时间
```

### 4.2 连线

「AI 自动连线」取轻形态：**边由节点引用推导，不独立存边表**。

- `foreshadows: [节点名]` = 出边（埋向谁）
- `payoffs: [节点名]` = 入边（回收谁）

连线图随时可从全部节点的这两组引用重画；如需更细语义（加深/强化），再扩一个 `kind` 枚举，
不改变存储形状。

## 5. 存储位置与生命周期

### 5.1 位置

住 `worldFlags.plotThreads`，每存档一份。照 ADR-32（`randomEvents`）/ ADR-33（`mapFacts`）
事实态先例：

- 零新 Dexie 表（随 `saveProfiles.variables.worldFlags` 进 FullBackup，随单存档导出/导入往返）。
- 按**节点名**为键寻址；休眠节点不删，名字回来自动复活。
- 刻意**不**塞进 `plotEvents` 表：那是大纲驱动的事件树（预生成、title 逐字一致、被
  `syncOutlineEvents` 维护），混入 AI 即兴节点会污染 title 寻址契约与上下文注入面。
  细化层是新语义，走新命名空间。

### 5.2 生命周期

```
pre_check 埋（active/dormant）→ 正文演绎 → post_check 结算（resolved / dissolved）
→ 已回收节点留在事件线里作为历史（不删），未回收伏笔保持 active 待后续回收
```

## 6. 写读归属

| 角色              | 职责                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `plot_pre_check`  | 读「当前活跃节点 + 未回收伏笔」快照 → 决定本轮埋新节点 / 更新既有 / 回收某个旧伏笔，输出节点声明（含 `foreshadows`/`payoffs` 引用） |
| `plot_post_check` | 正文落定后结算：这桩事兑现了 → `resolved`，不了了之 → `dissolved`；确认连线成立                                                     |
| 用户              | 游戏内事件线面板：节点 + 伏笔连线，照 PlotPanel 的剧透模式口径（未揭示节点蒙层）                                                    |
| 上下文注入        | pre_check 每轮注入事件线快照（活跃节点 + 未回收伏笔 + 近期回收记录）——「AI 自动连线」的原料                                         |
| Delta 会话        | 事件线快照纳入既有 `plot` scope 的投影；节点变化时走 delta 而非重基线                                                               |

## 7. 节奏闸门（Code 保证）

频率是 Code 的事，内容是 AI 的事：

- 种子化概率 + 冷却（每 N 轮至多一次）；战斗会话期间不产出。
- **密度随窗口距离递增**：离得远时世界只偶尔露峥嵘，临近窗口越来越明显，到窗口前刚好是
  「最后一根稻草」——避免「到点突然爆发」和「前奏提前透支爆点」两种失败。
- 伏笔链的连续性由记忆系统自然承接：已埋伏笔存在事件线节点里，pre_check 每轮可见。

## 8. 闭环

```
主线大方向（宏观）
 → pre_check 逐轮细化为 NPC/势力的具体行动（微观，带动机）
 → 行动间埋设伏笔（foreshadows）
 → 后续轮次回收伏笔（payoffs），行动累积成世界态势
 → 窗口到达 / 条件满足 → 主线事件正常触发 → post_check 正常结算
 → 进入下一方向，重复
```

主线不再是一张等待引爆的月历，而是始终在世界里发生的、由无数有动机的行动织成的进程——
主线事件触发的那一刻，世界已经为此走了很远。

## 9. 边界（明确不做）

- 不新建 Agent、不加新对话轮次。
- 不碰 `plotEvents` 表与大纲事件树的 title 寻址契约。
- 不改大纲本身：细化层是主线的实例化，服务主线，不修改主线。
- 不碰 ADR-32 事件系统：无关事件仍走现成事件定义，两者互不干扰。
- **伏笔回收不强制**：埋了伏笔没有「必须回收」的责任，回收是自然发生的——防止细化层
  退化成任务清单。
- 小事件不推进主线状态、不改世界线、不写 `delta_time`。

## 10. 对既有系统的影响（不变项清单）

| 系统                    | 影响                                                              |
| ----------------------- | ----------------------------------------------------------------- |
| 大纲事件树 `plotEvents` | 无（只读锚定，不新增节点）                                        |
| ADR-32 随机事件         | 无（职责分离，独立开关）                                          |
| `plot_pre_check` 模板   | 扩展输出契约（新增节点声明字段），既有 `triggeredEvents` 语义不变 |
| `plot_post_check` 模板  | 扩展输出契约（新增节点结算字段），既有结算语义不变                |
| 记忆系统                | 无（细化层自带结构化节点，不额外占用记忆）                        |
| FullBackup / 存档互传   | 自动包含（`worldFlags` 随 `saveProfiles` 往返）                   |
| 调试面板                | 增加事件线只读区块（照随机事件区块口径，判据全部复用生产函数）    |
