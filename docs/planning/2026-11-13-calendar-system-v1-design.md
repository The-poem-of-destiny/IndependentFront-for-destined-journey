# 日历系统 v1 设计

> **状态：P1–P3 已实施（2026-11-13；分支 `calendar-v1-key-dates`）。界面已在浏览器走查（桌面 + 375px 窄屏，占位内容 + 手工注入的示例数据）。真实内容包的节庆尚未转换成 `keyDates`，所以实际游玩时节庆一栏目前为空。**
> 📌 2026-11-13 更正：节庆来源改为世界书条目上的「关键日期」格式，见 [关键日期格式设计](2026-11-13-key-date-lore-format-design.md)。本文 §4.1 的「来源 B：`calendar` 内容分节」、§9 与 §10 第 1 条**已被取代**；D4–D9 读取 `annualWindow` 的规则改为读取 `keyDates`。其余部分（模式、生日、显示选择、存储、界面）仍然有效。
> 前提：角色年龄与生日（PR #145，`character-v1.1-age`）**按现状合并**，本设计不要求它再改字段。

## 1. 目标与边界

给玩家一个按存档独立的游戏内日历：看今天是哪天、哪些日子有节庆或生日、记下自己关心的日子。

v1 的三条硬边界：

1. **完全本地。** 日历不向任何 Agent 发送内容，也不接收任何 Agent 的写入。不新增占位符、不进提示词、不解析模型输出。
2. **按存档隔离。** 模式、玩家条目、显示选择都属于单个存档；删档连带删除，不跨档共享。
3. **只读游戏时间。** 日历不推进、不修改游戏时间，也不触发任何事件或提醒进入叙事。

不在 v1 范围：节日当天的叙事提示、生日事件、AI 创建日程、跨存档模板。

## 2. 现状（2026-11-13 实查）

### 2.1 引擎

| 已有                                                                  | 位置                                             | 对日历的意义                 |
| --------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------- |
| 历法算术：12 月 × 30 日、7 日一周、四季、单一纪元标签                 | `src/core/time/time-system.ts`                   | 月视图的格子与星期由它算     |
| 年度日期窗口 `LoreAnnualWindow { start, end, beforeDays, afterDays }` | 条目 `extra.lore.activation.readWhen.any[]`      | 唯一**结构化**的节庆日期来源 |
| 角色年龄锚点 `ageAnchor { startAge, month, day }`                     | `src/core/character/character-age.ts`（PR #145） | 生日来源                     |
| 场景面板里一行当前日期                                                | `ScenePanel.vue`                                 | 日历入口的自然落点           |

没有的：日历界面、日期事件的数据结构、「某天有什么」的查询。

### 2.2 真实内容包里的节庆

对私有内容仓世界书的清点（2026-11-13；原文含真实内容，不在公开仓）：写明日期的节庆共 35 个，只有 14 个是结构化的，且全部属于同一个势力；其余分散在世界总设定与另外几个势力的文化条目里，都是自由文本。12 个具名月也只存在于自由文本中。

由此得到四条设计上必须回应的事实：

1. **只读 `annualWindow` 的话，日历上只有一个势力的节庆。** 全大陆通行的节庆和其余势力都会缺席。
2. **节庆是分地区的。** 结构化的条目全部带地区限定，总览里还有更细的范围。日历项需要地区信息，筛选也应支持按地区。
3. **有多年一度的节庆。** 数据模型不能假定「每年重复」。
4. **自由文本的那些大多只有一行描述。** 为了进日历给每个都写一条完整的世界书条目，既重，又会顺带改变提示词行为（`annualWindow` 条目到日子会被喂给模型）。

## 3. 两种模式

| 模式         | 日历上有什么                                                             |
| ------------ | ------------------------------------------------------------------------ |
| **沉浸模式** | 只有玩家自己通过界面录入的条目。节庆与角色生日一律不出现                 |
| **普通模式** | 玩家条目 + 自动载入的节庆 + 已知角色的生日；玩家可按类别、地区或逐项隐藏 |

- **D1　模式按存档保存，可随时切换，切换不删除任何数据。** 玩家条目在两种模式下都存在；沉浸模式只是不派生自动来源。切回普通模式后，之前的隐藏选择原样保留。
- **D2　新存档默认普通模式**，只在日历弹窗里切换，建档流程不加步骤。
- **D3　沉浸模式下自动来源完全不计算**，不是「算了再藏」——筛选抽屉里也不出现节庆与生日两组，避免界面本身剧透某个节日或某人的生日存在。具名月属于历法本身，两种模式都显示。

## 4. 数据来源

日历上的每一项归一成同一个形状：

```ts
interface CalendarItem {
  /** 稳定键：`user:<id>` / `festival:<id>` / `lore:<条目 uid>` / `birthday:<characterId>` */
  key: string;
  kind: 'user' | 'festival' | 'birthday';
  title: string;
  note?: string;
  /** 地区标签（如「北境联盟」）；缺省 = 全大陆通行 */
  region?: string;
  start: { month: number; day: number };
  /** 缺省 = 单日；跨年窗口（12 月 → 1 月）合法 */
  end?: { month: number; day: number };
  /** 重复规则。缺省 = 每年 */
  repeat?: { everyYears: number; anchorYear: number } | { onceInYear: number };
}
```

### 4.1 节庆：两个来源合并（普通模式）

**来源 A — 世界书条目的 `annualWindow`。**

- **D4　扫描本存档启用的条目，`activation.readWhen.any[]` 中任一分支带 `annualWindow` 即产出一项。** 不解析条目正文。
- **D5　日期取 `start`–`end`，忽略 `beforeDays` / `afterDays`。** 后两者是「提前多久把设定喂给模型」的预热量，不是节庆本身的日期。
- **D6　标题取同一 `readWhen` 里关键词分支的第一个关键词**（现有结构化条目都有）→ `lore.summary` → 条目名去掉方括号。
- **D7　地区取带 `annualWindow` 的那个分支的 `locations[0]`。**
- **D8　不展示条目正文。** 正文可能含 EJS，也可能含玩家尚未得知的设定。
- **D9　旧模式存档同样可用。** `readWhen` 的**激活**只在 Story v2 生效，但日历读的是元数据本身。

**来源 B — 新增内容分节 `calendar`**（内容目录 `data/content/calendar.json`，内容包可整份替换；引擎占位为空）。

```json
{
  "monthNames": ["（十二个具名月）"],
  "festivals": [
    { "id": "new-year", "name": "新年", "month": 1, "day": 1, "note": "岁首" },
    { "id": "founding-day", "name": "建国节", "month": 5, "day": 27, "region": "中央帝国" },
    {
      "id": "grand-expo",
      "name": "博览会",
      "month": 12,
      "day": 19,
      "endDay": 21,
      "region": "雾港",
      "everyYears": 4,
      "anchorYear": 488
    }
  ]
}
```

- **D10　这一分节承载「只需要出现在日历上」的日期与具名月。** 它回应 §2.2 的事实 1、3、4：全大陆通行的节庆、其余势力的一行节庆、多年一度的周期、12 个具名月，都不需要为此新建世界书条目，也不改变任何提示词行为。
- **D11　两个来源按标题去重，同名时 B 的字段优先。** 这样内容作者可以用 B 给某个 A 来源的节庆补备注或更细的地区，而不会出现两条。
- **D12　容错解析，永不抛**：坏条目整条跳过，整份认不出当空。口径同 `random-event-pack.ts`。

**两个来源共同的规则：**

- **D13　每次打开时现算，不落库。** 内容包更新后节庆跟着变；消失的条目其隐藏键成为无害的孤儿。
- **D14　31 日并到 30 日**，与生日口径一致（引擎每月 30 天）。

### 4.2 角色生日（普通模式）

- **D15　来源是本存档 `characters` 表里 `type` 为 `player` / `npc`、带合法 `ageAnchor` 的角色。** 怪物与召唤物不算。角色只有登场后才有记录，所以「已知角色」天然等于「已登场角色」。
- **D16　只显示「生日是给定的」角色，判据从现有字段推导，不新增字段。** `ageAnchor` 本身不记录生日是给定的还是兜底的，但线索原件仍留在角色记录上：`definition.birthday`（作者定义）或 `customFields.birthday`（主角建号 / `entity_gen` 输出）任一能被 `parseAgeHint` 解析出生日，即视为给定。两者都没有的角色生日是兜底的 1 月 1 日，不进日历——否则 1 月 1 日会堆满所有没给生日的路人。在 `character-age.ts` 增加一个只读判定函数即可。
- **D17　标题为角色名，附「满 N 岁」**，N 由 `ageAt` 按所看年份算出；所看年份早于角色出生的不显示。

> 📌 D16 的现实后果：在生成角色的提示词开始要求模型输出 `birthday` 之前，日历上的生日基本只有作者在原生定义里填了生日的角色。旧世界书人物资料里没有结构化的生日。

### 4.3 玩家条目（两种模式）

- **D18　玩家可新增、编辑、删除**：标题（必填）、备注、起止日期、每年重复或仅某一年。
- **D19　玩家条目不能编辑自动项。** 想改某个节庆的显示，只能隐藏它再自己建一条。

## 5. 显示选择

- **D20　存「隐藏了什么」，不存「显示了什么」。** 新登场的角色、新装内容包带来的节庆默认可见。
- **D21　三层开关**：类别（全部节庆 / 全部生日）、地区（某势力的全部节庆）、逐项（按 `CalendarItem.key`）。上层关闭时下层选择保留但不生效。
- **D22　提供「只看所在地区」快捷筛选。** 按主角当前位置路径匹配节庆的 `region`，无地区的全大陆节庆始终显示。这是纯本地的显示过滤，读的是存档状态，不经过 AI。默认关闭。
- **D23　玩家条目不参与隐藏**——不想看就删。

## 6. 存储

```ts
interface SaveCalendar {
  saveId: string; // 主键
  mode: 'immersive' | 'normal';
  entries: CalendarUserEntry[]; // 玩家条目
  hiddenKinds: Array<'festival' | 'birthday'>;
  hiddenRegions: string[];
  hiddenKeys: string[];
  localRegionOnly: boolean;
  updatedAt: number;
}
```

- **D24　新增 Dexie 表 `saveCalendars`（v33），每存档一行。**
- **D25　不进快照载荷。** 日历是玩家的笔记，不是世界状态：回退一个回合不应该抹掉玩家刚记下的日子。放进 `SaveProfile.worldFlags` 会被快照连带回退，这是不选它的原因。
- **D26　进整库备份与单存档导出，删档级联删除。** 单存档导入会重发角色 id，`hiddenKeys` 里的 `birthday:<characterId>` 必须随之重映射（`session-backup.ts` 已为编年史做同样的事）。
- **D27　缺行即默认值**（普通模式、空条目、无隐藏）。旧存档无需迁移，首次修改时才写入。
- **D28　写入走 `withSaveWriteLock`，锁内重读后窄改。** 与 `persistFocusQuest` 同一条纪律。

## 8. 界面

- **入口**：侧边工具栏新增「日历」；场景面板的日期行可点击，打开同一弹窗。
- **月视图**：7 列星期网格，30 天按 `time-system` 算出的星期落位。页头显示纪元 + 年、月份（有具名月时一并显示月名）+ 季节。今天高亮；有项的日子显示标记，按类别区分样式。上一月 / 下一月 / 回到今天。
- **当日详情**：点某天列出当日所有项，节庆带地区标签；玩家条目可编辑、删除，自动项可一键隐藏。
- **近期列表**：未来 30 天内的项按日期排列。窄屏下以它为主视图，月网格折叠。
- **新增条目**：标题、备注、起止日期、每年重复或仅当年。
- **筛选抽屉**（仅普通模式）：节庆按地区分组，生日单列一组；各级带总开关与逐项勾选，另有「只看所在地区」。
- **模式切换**：在弹窗设置区；切换时说明「数据不会丢失」。

组件 `src/ui/components/game/CalendarPanel.vue` 及子组件，状态放 `calendar-store`（Pinia）。排版、间距、弹窗外壳遵循 `docs/design.md`。
