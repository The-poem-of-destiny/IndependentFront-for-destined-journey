## 1. 执行摘要

本项目已经形成清晰、独特且完成度较高的叙事 RPG 产品形态。首页、角色创建、游戏主界面、设置、存档管理与创意工坊之间具有一致的视觉语言；引擎侧具备多 Agent 编排、存档级提示词会话、QuickJS 隔离、快照恢复、内容包与工坊扩展等较深的系统能力。自动化测试与分层约束显著强于同类项目。

然而，当前产品尚不具备面向一般新用户发布所需的安全性、首次运行完整性、故障可解释性、可访问性和分发能力。审查确认两项发布阻断级问题：

1. 剧情事件的 `triggerCondition` 可进入宿主页面的 `new Function`，从模型输出或导入备份形成可达的同源任意 JavaScript 执行汇点；
2. 角色创建中被判定为禁用的选择仍可通过卡片内部按钮写入状态，并最终形成违反创建约束的存档。

除上述 P0 外，首次运行路径还存在一项结构性矛盾：应用将“新建存档”作为首要行动，但未在进入八步角色创建前验证内容包、API 端点、模型与 Agent 映射是否就绪。用户可以完成全部创建流程，进入游戏后才因模型未配置而收到缺乏具体原因和修复入口的通用失败提示。

本次审查合并重复根因后共登记：

- **2 项 P0：** 可直接破坏安全边界或承重状态约束，应阻断发布；
- **15 项 P1：** 影响主流程可靠性、数据一致性、凭据安全、可访问性、分发或工程治理；
- **16 项 P2：** 明显降低可理解性、信任、成本控制、性能或回归安全性；
- **9 项 P3：** 有界的维护性、披露、资源消耗与界面抛光问题。

## 7. 发布阻断项（P0）

### 7.1 CRIT-01：剧情触发条件可执行宿主域 JavaScript

- **触发源：** 被提示注入影响的 `plot_post_check` 输出可创建 `newChildEvents[].triggerCondition`；导入的单存档备份也可携带同字段；
- **可达路径：** `game-pipeline.ts:1847-1854` 将原始后检输出交给 `postCheckPlot`，`plot-engine.ts:276-323` 原样持久化子事件条件；待处理事件及其条件会再次提供给 Plot Agent（`agent-templates.ts:383-400`），当模型选择相应事件后，`preCheckPlot` 调用 `evaluateCondition`；
- **根因：** `plot-engine.ts:27-56` 将条件字符串插入 `new Function`。源码注释称“限制可用全局”，实现中不存在任何全局限制；
- **影响：** 代码在应用同源环境中执行，可读取 IndexedDB 中的存档与 API Key、localStorage 中的设置与工坊令牌、调用同源 BFF、修改游戏数据或向外部发送数据；
- **备份入口：** `session-backup.ts:648-681,695-751` 只校验顶层结构，并通过对象展开保留剧情事件其余属性；
- **验证边界：** 源码路径确认该代码执行汇点可达；本次审查未执行攻击载荷，不将其表述为已完成的动态利用演示；
- **修复要求：** 使用不可执行的条件表达式解析器，或复用已有 QuickJS 隔离后端；模型输出与导入数据在持久化前均须经过同一 schema/语法白名单；补模型输出、导入备份和宿主全局不可达三类回归测试。

### 7.2 CRIT-02：禁用创建选择可绕过资格与点数约束

- **触发源：** 玩家点击被视觉标记为禁用的装备、物品或技能卡片内部“选择”按钮；
- **根因：** `SelectableCard.vue:18` 附近的内层按钮仍可发出选择事件；`create-store.ts:695` 起的 mutation 不调用 `canSelect`；最终 `startJourney()` 也没有重新执行完整创建约束；
- **影响：** 可产生负点数、种族或身份资格不满足的持久存档；
- **现有登记：** `docs/known-issue.md` UI-01；
- **修复要求：** 组件禁用、store mutation 校验和最终提交校验三层同时落地，并分别增加回归测试。

## 8. 高优先级问题（P1）

### 8.1 SEC-01：整库备份导出的 JSON 包含未脱敏 API Key

`ApiEndpoint.apiKey` 的接口类型为字符串（`types.ts:335-354`）。`FullBackup` 明确包含 `apiEndpoints`（`database.ts:711-750`），`exportAllData()` 原样读取该表（`:772-845`），设置页再直接 `JSON.stringify` 为可读下载文件（`DataSection.vue:367-377`），过程没有脱敏。本结论只针对导出表示，不对浏览器存储的物理加密状态作未经验证的判断。

设置页说明详细列出音频、素材和内容包不随备份导出，却没有说明凭据会进入备份（`DataSection.vue:451-483`）。与此相对，localStorage 持久化会主动清空 Key（`settings-store.ts:126-136`），说明整库导出绕过了已有的凭据边界。

**修复要求：** 默认从备份中排除 API Key；如需支持凭据迁移，应采用独立、显式确认且清楚标记敏感性的导出流程。

### 8.2 SEC-02：本地 BFF 对普通 Web Origin 开放条件性高风险能力

`server/app.ts:74-103` 仅拒绝 `Origin: null`，随后为其他来源返回 `Access-Control-Allow-Origin: *`，并允许调用方提供 `Authorization`、`api-key` 与 `X-Target-Base-URL`。`proxy.ts:17-30,47-102` 允许调用方指定上游，且刻意保留 localhost 与私有 IP，以支持本地模型。BFF 不会自动附加应用已存储的 Key；风险来自跨站调用方自带凭据或访问无需凭据的本地能力。

固定路由仍可调用本地 chat/models/embeddings、NovelAI 与 ComfyUI 的 prompt/history/view/queue/interrupt；内容路由在配置 `POEM_CONTENT_DIR` 后可将未设大小上限的文本请求体写入 `.json` 文件（`content.ts:43-87`）。Windows 启动器发现相邻私有内容仓时会自动启用该目录（`dev.bat:23-42`）。

**限定因素：** Vite 当前默认仅监听 loopback，跨站浏览器利用是否成立取决于 Private Network Access 等浏览器限制；浏览器扩展与本地进程不受同等限制。因此本项按条件性高风险登记，而非声明所有浏览器均可直接利用。

**修复要求：** 将 BFF 限定为可信 Origin，并引入不可由外部站点获得的会话能力；内容写回需要独立授权、请求体上限和明确的开发模式边界。

### 8.3 ONB-01：首次运行缺少就绪门，失败暴露过晚

README 要求配置三个 API 并为 Agent 绑定模型，但首页在未验证内容包、端点、模型和 Agent 映射时仍将“新建存档”作为主行动。用户可以完成八步创建；首次进入游戏后，各 Agent 因未配置模型失败，界面只显示“世界的回应在此中断，可以再次尝试”，具体原因仅写入 console（`game-pipeline.ts:478-512,756-774`）。

API 空态本身具有较清楚的说明，但用户必须在失败后主动找到设置页；Agent 设置呈现 12 个警告状态，没有一键应用推荐映射或配置完成度。

**修复要求：** 在角色创建之前加入首次运行清单：内容包状态、API 必填校验、连接测试、推荐 Agent 映射、Embedding 可选性、预估调用数量与成本。失败卡片应显示具体原因并直接跳转到对应设置分区。

### 8.4 DATA-01：新旅程创建非 single-flight、非事务且错误不可见

`CreatePage.vue:29-37` 未设置 creating/busy 状态；最终按钮只受步骤合法性控制；失败只写 `console.error`。`create-store.ts:1784-1852` 依次写角色、存档、profile、命运点、剧情大纲和事件，没有统一事务或回滚。

双击可启动两次创建；中途失败可留下孤儿角色或半份存档。

**修复要求：** 提供 engine 级 `createJourney` 事务、UI single-flight 锁，以及可见且可重试的错误状态。

### 8.5 LIFE-01：活跃存档双所有者与异步装载竞态

`ui.activeSaveId` 与 `game.activeSaveId` 是两个独立 ref。导航先修改前者，`game-store.loadSave` 经过多个 await 后无 generation、requestedSaveId 或 disposed 检查地提交后者及整份投影（`ui-store.ts:34-50`；`game-store.ts:981-988,1033-1078,1113-1148`）。

当用户打开慢加载存档 A 后迅速返回并打开 B，A 的异步完成可能覆盖 B 的角色投影，或让已卸载页面继续构造 pipeline、消费开场提示。

**修复要求：** 建立唯一 `SaveSession` 所有者；每次装载捕获 requestedSaveId 与 generation，并在每个 await 后验证；`loadSave`、`restoreMessages`、`refreshFromDb` 接收显式 saveId 并采用 last-load-wins 提交栅栏。

### 8.6 LIFE-02：Stop 后旧回合与新回合共享可变状态

`GamePipeline` 将 `currentContext`、`pendingPlotTasks`、`pendingAudioMarker`、`lastStoryMessage` 与 `chainData` 保存在共享实例上（`game-pipeline.ts:232-282`）。Stop 会提前允许新输入，而旧回合可能仍在等待不响应 abort 的剧情或 embedding 任务。新回合覆盖字段后，旧 finally 可读取或清理新回合状态（`:387-422,514-556,638-642`）。

**修复要求：** 每次运行创建独立 `RunSession`，共享 pipeline 只保留 currentRun 指针；或在旧 run 完整收尾前不解锁输入。

### 8.7 EFFECT-01：效果接线未与权威投影做增删对账

`effect-wiring.ts:56-83,132-164,187-217` 对 owner 做幂等添加，但不会删除权威角色投影中已消失的 owner。除显式 `unequip_item` 与时间线恢复外，替换装备、删除或转移物品、更新脚本、删除或更新技能、删除角色及删档均缺少统一拆线。

结果是已移除的装备或技能仍可能响应事件，新脚本也可能因旧 owner 已存在而永远不注册。

**修复要求：** 提供唯一 `reconcileEffectWiring(saveId, characters)`，按权威 owner 集合做 diff；在装载、角色提交、页面/会话销毁及删档时统一调用。

### 8.8 STATE-01：StateManager 原子契约与部分成功实现冲突

`state-manager.ts:1-12,184-199` 将公开契约描述为全部成功或全部回滚，但实际执行在单条 patch 失败后继续后续 patch，并无条件 flush 成功部分（`:350-448,586-595`）。测试明确固定了部分成功行为（`state-manager.test.ts:3456-3480`）。

制作、战斗与重铸调用方仍把提交当作原子领域命令；材料扣除失败时，HP、经验、FP 或产物信息仍可能部分生效。

**修复要求：** 拆分显式 best-effort AI patch API 与 atomic domain-command API；制作、战斗、重铸和建档应完整预验证，并在同一 Dexie 事务与 save lock 内提交。

### 8.9 REL-01：无可分发安装包或生产 BFF 入口

README 已明确当前为开发版且无独立安装包（`README.md:19-31`）。`docs/ARCHITECTURE.md:300-304` 说明 `buildHonoApp()` 仅挂载于 Vite dev/preview，没有独立进程入口或打包产物。

当前新用户必须安装 Node、下载源码、安装依赖并运行开发服务器，无法按一般桌面应用或受支持静态服务使用。

**修复要求：** 在 `TODO.md`“正式发布打包”中裁定桌面壳、静态站+BFF 或双形态方案，并定义版本、更新、内容包、凭据与首次启动策略。

### 8.10 A11Y-01：既定键盘与 WCAG 契约未兑现

`PRODUCT.md:49-54` 要求 WCAG AA 与键盘可用，但共享 `AppModal.vue:76-108` 缺少 `role="dialog"`、`aria-modal`、标题关联、初始焦点、焦点陷阱和焦点归还。Toast 无 live region（`ToastContainer.vue:21`）；首页存档行、难度卡片和背景卡片使用可点击 div，缺少键盘等价行为（`HomePage.vue:645`、`CreateStepDifficulty.vue:23`、`BackgroundList.vue:110`）。

**修复要求：** 先修共享基元，再修必选流程控件；加入真实键盘遍历与 axe/ARIA 回归测试。

### 8.11 RESP-01：窄视口下首页和游戏主界面不可用

390×844 实测中，内容状态横幅逐字换行并覆盖首页标题与主行动。游戏页仍保持固定桌面画布；`GamePage.vue:488` 的 `min-width: 900px` 导致页面水平裁切，仅显示局部内容。设置页可堆叠，但导航需要横向发现。

该问题与 `docs/known-issue.md` UI-02 及 `TODO.md`“多分辨率 / 多宽高比适配”“移动端支持”一致。

**修复要求：** 在支持完成前明确声明最低桌面宽度；正式修复需建立紧凑桌面态和移动/窄屏状态，而非继续压缩三栏桌面布局。

### 8.12 BUILD-01：本地忽略音频可静默进入构建产物

Vite 会复制 `public/` 下的忽略文件（`.gitignore:73`、`vite.config.ts:156`）。本机当前工作副本的成功构建包含 57 个 MP3，共 265.98 MiB，使 `dist-ui` 达 309.66 MiB；运行时 manifest 仍为空。`public/audio/README.md:81` 已说明部分本地曲目未获分发授权。由于这些文件被 Git 忽略，干净克隆与 CI 不包含同一音频集合；风险属于主机状态污染发布产物，而非可复现的仓库基线产物。

**修复要求：** 发布构建采用显式 allowlist，而不是依赖人工清理；CI 对产物路径、数量、体积与许可清单做断言。

### 8.13 DEV-01：开发启动器会终止非项目进程

`dev.bat:45-63` 对 5173–5179 的全部监听进程执行 `taskkill /F`，`dev.sh:43-55` 使用 `kill -9`，均未验证 PID 是否属于本仓库。

**修复要求：** 只清理由本项目记录的 PID；其他端口冲突应报告并退出，或要求用户显式确认清理。

### 8.14 TOOL-01：Node 版本声明低于当前依赖要求

README 声明 Node 18+（`README.md:31`），当前 Vitest 要求 Node 20+，jsdom 要求 20.19+（`package-lock.json:6298,4615`），而 `package.json` 无 `engines`、`packageManager` 与版本文件。

**修复要求：** 统一为 Node 20.19+，增加版本与包管理器约束，并将贡献者安装命令改为可复现的 `npm ci`。

### 8.15 GOV-01：`master` 无分支保护和必需检查

2026-08-29 的 GitHub 只读查询返回 `protected: false`，required checks 与 enforcement 均为空。仓库虽有完整 CI，但远端未强制代码合并前通过 `types`、`quality` 与 `test`。仓库明确允许经过本地格式检查并在推送后验证 CI 的纯 Markdown 直推；本项不否定该有意工作流，而是指出代码与配置变更缺少远端强制门禁。

**修复要求：** 为 `master` 启用分支保护并要求三项 CI job；限制绕过权限并保留紧急回滚流程。

## 14. 结论

本项目的主要矛盾不是功能数量不足，而是核心系统深度已经超过首次运行、生命周期所有权、安全披露和发布工程的成熟度。继续增加内容或子系统会扩大这些边界问题的影响面。
