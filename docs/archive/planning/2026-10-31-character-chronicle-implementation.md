# 原生角色与编年史实施计划

状态：已实施并完成本地验收（2026-10-31）。依据本次确认的中文设计与角色查看器演示；以磁盘上的现行目录为准，基线 `d9162cc`。现行使用方式及协议见 [原生角色与编年史](../../reference/character-system.md)。

## 目标与边界

角色成为拥有初始档案、素材关联与初始经历的独立定义；每份存档维护角色当前状态和编年史。编年史位于现有角色查看器的档案旁。主叙事一次回复同时输出正文和 `<character_updates>`，不新增 Agent，也不为记录经历增加模型请求。已有 `entity_gen` 只负责新角色的机械数据补全，并沿用叙事已建立的资料。

经历重要度为 0–10，自动上下文门槛为 7，并受角色相关性与独立字符预算限制。日常记录对玩家仍可见。过去时间保留原有精度；不新增剧透、隐藏或发现状态，不让模型任意重写旧事件，不追溯编造旧存档的历史。

## 实施顺序

1. **角色定义与内容入口**：明确叙事字段白名单；接入原生角色定义，保留素材引用。旧资料采用可审查的转换入口，保留源文本和条目身份，不执行旧脚本、不删除原资料。新存档冻结所选定义，后续内容更新不覆盖游玩状态。
2. **持久化与生命周期**：增加按存档、角色索引的经历表；快照包含经历，回退同时恢复档案与经历；整库及单存档备份携带经历并重映射来源和角色关联，删除存档级联清理。旧快照没有经历时按未记录处理。
3. **叙事读写闭环**：解析 `<character_updates>`，逐角色校验；模型按名字寻址，代码生成 ID、来源指纹和本轮时间。新人物先实体化，同回合重复提交幂等，坏条目明确告警且不清空原数据。普通及 v2 回合共用提交入口。
4. **提示词与界面**：普通/Delta/v2 均收到协议与筛选后的重要经历；原生定义替代对应的旧人物 lore。查看器增加全部/重要、搜索、排序、过去/旅程分组和经历详情，保留其他页签、主题与移动布局。
5. **验证与文档收口**：执行针对性 Vitest、真实浏览器界面检查和仓库八道闸门；同步字段规范、架构说明与变更记录，记录尚未验证的真实模型行为。

## 验收证据

- 同次叙事产生正文与角色更新，流式与最终正文不泄漏 JSON；缺块与坏块可区分。
- 重要度 1 的聊天可以搜索但不会自动注入；重要度 9 的事件仍受角色相关性与预算限制。
- 初登场人物拥有一致的档案和大致过去；提到另一个人不会自动给其增加亲历。
- 重复提交不重复记录；回退/重生成恢复正确分支；切档和备份导入不串数据。
- 角色查看器保留六个原有页签并增加编年史，空态、来源详情、筛选和窄屏可用。
- 原资料与素材关联保留，未成功转换的条目不静默丢弃；旧存档不会自动补造过去。
