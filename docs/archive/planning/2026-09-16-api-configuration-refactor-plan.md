## 1. 实施顺序

先完成能证明旧 OAI 行为保持成立的协议基础，再加入原生协议，最后统一消费方和配置激活。所有阶段使用同一类型与发送入口，避免界面先暴露尚未实现的协议。

| 阶段 | 内容                                        | 依赖   | 退出条件                                               |
| ---- | ------------------------------------------- | ------ | ------------------------------------------------------ |
| T0   | 锁定数据与行为契约，记录现有 OAI 和配置基线 | 无     | 严格读取、请求体优先级、会话消息模型都有可测试输入输出 |
| T1   | 统一源类型、校验、参数合并与配置快照        | T0     | 覆盖/省略规则、受保护字段、实际输出预算通过测试        |
| T2   | 提取 OAI 适配器与受控 BFF 传输              | T1     | 现有普通、流式、工具调用与中转兼容回归通过             |
| T3   | Gemini 与 Claude 原生适配器                 | T2     | 三种协议均能完成多轮工具续接及流式错误处理             |
| T4   | 通用源/图像连接存储及配置界面               | T1、T3 | 旧数据不被改写、两页独立管理、参数与测试接线完成       |
| T5   | 所有 LLM 消费方与 Delta/战斗会话接线        | T3、T4 | 无遗漏调用点、无原生签名丢失、无失效绑定换源           |
| T6   | Embedding 统一绑定及 Reranker 记忆链路      | T2、T4 | 写入查询同配置、重排有作用、取消/失败回退正确          |
| T7   | 全链路回归、真机走查、文档状态收口          | T5、T6 | 闸门通过，真实协议验收及未验证项如实记录               |

T4 的 schema 与严格读取代码可以先作为未启用实现准备；只有 T5、T6 接线就绪后才在发布构建启用新 schema 和新表单。不能发布新旧消费方混用不同配置形状的中间版本。

## 2. 分阶段任务

### T0：契约和基线

- 实施前重读根目录及对应源码目录的 `AGENTS.md`；UI 实施前读 `docs/design.md`，Delta、图像、RPM、字段规范按设计引用读取。
- 复核当前 `ApiSection`、`AgentClient`、战斗双角色链和设置迁移的未提交变更，确定实际分支基线。
- 定案 `kind/protocol` 联合类型、原生消息续接结构、参数受保护字段、body 合并/省略次序。
- 用脱敏合成 fixture 固化当前 OAI 请求、SSE、中转响应包装和旧 API 配置拒绝行为；禁止导出用户实际密钥。
- 明确三种召回升级情况：旧 LLM、旧 Embedding、查询/写入源冲突；保持用户确认的源参数优先级。

### T1：类型和参数基础

拟新增：`src/sillytavern/types-api.ts`、`src/sillytavern/api/source-config.ts`、`src/sillytavern/api/body-parameters.ts`。

- `types.ts` 作为统一类型出口；UI 不再单独声明不同字段集的 API 条目。
- 配置统一严格解析：缺失或未知用途/协议直接报错，不通过模型名、域名或旧字段推断默认值。
- JSON 深合并、数组替换、JSON Pointer 省略、保护字段、危险键拒绝。
- 输出不可变调用快照、实际参数及可用的输出预算，供会话签名和调试共用。
- 保持输入数据不变，防止一次测试调用污染已保存源或 Agent 设置。

### T2：OAI 适配器与传输

拟新增：`src/sillytavern/api/llm-runtime.ts`、`llm-adapter.ts`、`openai-chat.ts`、`transport.ts`；BFF 可增加 `server/routes/llm.ts`。

- 从 `AgentClient` 提取请求体、非流式响应与 SSE 解析，保留现有外层重试和业务回调。
- 统一测试、模型列表和正式请求的协议路由与凭据，取消组件里的手写测试 fetch。
- BFF 复用 `forward`，增加所需头、固定操作路由与上游取消；回归已有 SSRF、重定向、压缩头和 SSE 策略。
- 新旧接口兼容期采用单实现转发，不能保存两份合并逻辑。
- 流式与非流式的自定义参数必须一致，`stream_options` 仅在适用调用发送；源省略配置能处理不支持它的中转。

### T3：原生 Gemini、Claude

拟新增：`src/sillytavern/api/gemini.ts`、`anthropic-messages.ts`。

- 按显式协议实现模型列表、普通生成、流式生成、工具 schema 与工具选择映射。
- Gemini 保留 parts 顺序、函数关联与 `thoughtSignature`；Claude 保留原生 content blocks、thinking/signature 和工具 ID。
- 标准化可见文本、工具结果、finish reason、usage，保留原始诊断字段。
- 普通 system、仅 system、多个前置 system、工具后 user 等输入形状写映射测试；不将不受原生协议支持的中途 system 静默提升成全局指令。
- 不能完整表达的请求结构在本地失败；不把本地转换失败当成网络错误反复重试。

### T4：存储、严格激活、配置页与图像页

拟新增：`src/ui/stores/api-source-store.ts`、设置页 `api/` 子组件，以及 `image/ImageConnectionCard.vue`。

涉及现有：`settings-store.ts`、`settings-types.ts`、`api-key-migration.ts`、`ApiSection.vue`、`ImageRenderCard.vue`、`scene-image-seams.ts`、`database.ts`。

- 以现行数据库下一版本增加图像连接表；不增加配置迁移记录表，也不在版本升级中扫描端点。
- 通用源启动时严格校验当前 schema；旧行失败时保持原样，不写回、不补字段、不搬运。
- 图像连接从图像页显式设置，出图查询只读图像存储；旧 image 端点不会自动转入。
- `image_prompt` 继续使用 LLM 源选择器，实际出图的认证字段留在专用连接卡。
- 通用页按用途分类；LLM 显示协议、模型、参数、测试；图像类型选项退役。
- 通用源及图像连接均进入凭据引用索引；RPM 改为事务内按变更行更新，避免跨页面整表覆盖。
- 复核 FullBackup、单档导入、恢复、清库、重置、HMR/销毁后的写入行为；普通备份不带新连接表与 body。

### T5：LLM 消费方和会话

涉及现有：`endpoint-resolver.ts`、`game-pipeline.ts`、`create-store.ts`、`journey-readiness.ts`、`AgentParamsCard.vue`、`agent-orchestrator.ts`、`prompt-session-assembler.ts`、`combat-v3/agent-session.ts`、`combat-v3/coordinator.ts`。

- 主 DAG、捏人/大纲、角色/物品/制作侧链、图像提示词、战斗主持人与敌方均经统一类型化解析入口。
- Agent UI 与运行时都限定 LLM；明确保留用户显式绑定失效时拒绝换源的语义。
- `chatWithTools` 输出完整可续接增量，战斗持久会话停止从工具日志重建消息。
- Delta 签名包含协议和参数配置，预算读取实际输出上限；成功后才推进 transcript。
- 配置变更于业务调用边界生效，同一工具循环/重试不混用新旧源，角色历史和 Kernel 权限不受协议转换破坏。
- Debug 保留必要诊断，密钥、原生不透明签名和自定义 body 的敏感值不进入普通可分享导出。

### T6：Embedding 与 Reranker

拟新增：`src/sillytavern/api/embedding.ts`、`reranker.ts`、`server/routes/rerank.ts`；检索编排可抽为 `src/sillytavern/memory-retrieval.ts`。

涉及现有：`MemorySection.vue`、`memory-store.ts`、`memory-summarizer.ts`、`agent-orchestrator.ts`、`game-pipeline.ts`。

- 2026-09-16 补充裁定：协议分别为 `openai-embeddings` 与 `openai-rerank`，复用 OpenAI 兼容连接配置、Bearer 鉴权和传输实现，仅按用途区分请求体、操作路径与响应解析。
- 增加显式召回模式、Embedding/Reranker 绑定及候选数设置；不根据旧模型名推断模式或派生连接。
- 读写向量共用配置，处理实际维度、参数指纹、旧空间兼容及 key 轮换。
- 先生成有边界的候选池，再通过 `openai-rerank` 调用 `/rerank`，最后按最终召回数裁剪；不能先取最终 K 再声称获得更大范围的重排效果。
- Reranker 参数覆盖、索引校验、部分结果补齐、错误回退和取消接线。
- 区分“未启用”“绑定失效”“上游失败”“正常无结果”，提供非致命诊断；保存设置不自动重嵌入旧记忆。
- 保持当前存档和记忆可见性，沿用下游输出/注入契约。

### T7：验收和文档

- 修改过的代码运行针对性测试及 Vue/引擎/工具类型检查；最终提交前运行 `npm run gates`。
- 按下表完成协议与 UI 验收。真实服务不可用时明确记为待验，不以 mock 通过替代。
- 更新设计文档状态、两份源码导航、架构总览与完成记录；已交付实施计划按归档规则处理。
- 仅格式化本次实际改动文件，中文文档执行 U+FFFD、控制字符检查。
- 若用户随后要求提交，按仓库分支/PR/合并规则执行，并在 push 后检查 CI。

## 3. 必要验证矩阵

| 验证面     | 场景                                                    | 通过标准                                                       |
| ---------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| 参数       | Agent 与源同名、嵌套对象、数组、null、省略字段          | 源优先；与预览、实际预算一致；不修改原配置                     |
| 参数       | 受保护字段、危险键、非法 JSON、协议互斥项               | 发包前明确失败，不能变成静默修正                               |
| OAI 回归   | 普通/SSE/工具轮次/中转包装                              | 原有有效行为保留，覆盖参数全部生效                             |
| 原生协议   | Gemini、Claude 各自普通与流式                           | 文本、usage、结束和错误正确归一化                              |
| 工具续接   | 连续轮次、多工具、原生签名、畸形参数                    | 原生块保留；未完成参数不执行；权限不扩大                       |
| 持久会话   | 战斗多决策、角色切换、Delta 跨回合                      | 无串历史；不丢工具上下文；前缀稳定                             |
| 配置热更新 | 同 ID 修改 URL/Key/协议/模型/body                       | 旧调用快照完成，新调用重建正确基线                             |
| 类型绑定   | image/embedding/reranker 误绑普通 Agent、删除显式源     | 不向错误用途或其他供应商发请求                                 |
| 向量       | 读写同源、参数/模型变更、Key 轮换、旧空间               | 仅兼容空间算余弦，不触发隐蔽重嵌入                             |
| 检索接口   | `openai-embeddings` 与 `openai-rerank` 共用连接及鉴权   | 分别请求 `/embeddings` 和 `/rerank`，模型/参数独立，同凭据共桶 |
| 重排       | 正常、部分结果、越界/重复索引、非有限分数、空结果、超时 | 排序正确、映射本地候选、异常恢复原候选                         |
| 配置激活   | 当前源、旧字段行、旧图像行、缺失绑定、重复启动          | 当前源正常；旧配置报错且零写回，不自动搬运或派生               |
| RPM        | 跨用途/协议/页面同凭据、改 Key、删除引用、取消          | 共桶及策略保留；局部保存不覆盖别页                             |
| 备份       | 新旧整库、单档、恢复、清库                              | 凭据/自定义 body 不进入普通备份；本机凭据不被导入覆盖          |
| UI         | 宽屏、390px、键盘、reduced motion、错误草稿             | 可完成配置、修改、测试、保存和错误恢复                         |
| 图像回归   | 重新配置 NovelAI 连接后手动出图、ComfyUI 出图           | 连接可用，原有模型、方言、去重与额度规则成立                   |

真实调用验收由实施阶段明确执行，优先使用用户提供的测试源与小输入；图像验证是明确的生成操作。设计阶段不读取用户浏览器里的密钥或执行付费调用。

## 4. 仍属建议的实施细节

以下不影响本轮设计落盘，实施时可据代码和验证结果收敛，并在设计中更新理由：

- 组件拆分粒度与源列表的最终视觉布局。
- Reranker 候选池默认倍率、总文本预算及服务商长度限制。
- JSON 编辑器的选型和原生协议可选参数提示范围。
- 只读 `settings.apiPool` 当前 schema 投影的具体退役时点。

核心范围与源参数优先级以用户已确定要求为准，不能因为实现方便退化成只有 OAI 外壳的三种标签。
